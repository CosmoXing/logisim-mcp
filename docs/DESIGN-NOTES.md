# 设计取舍

记录几个"本来可以更省事，但故意没那么做"的决定，以及踩过之后才明白的道理。

## 1. 宁可失败，不要静默降级

反面教材：早期版本遇到不认识的元件，`_ports()` 返回空字典。结果该元件从网表里消失，
仿真照常给出一个看起来合理的答案。用户拿着这个答案去交作业，打开 Logisim 才发现是错的。

现在：`netlist.py` 抛 `UnsupportedComponent`，带上元件名与坐标；`circ_audit` 返回 `verdict=unsupported`；
`circ_build` 遇到位宽不一致直接拒绝并列出明细。

代价：多写不少错误分支，且每加一个元件都要补齐支持清单。
收益：任何"工具说没问题、实际有问题"的场景，从"偶发"变成"不可能"。

## 2. 两套几何，故意重复实现

`geometry.py`（生成）和 `netlist.py`（解析）各写了一遍端口公式，看起来违反 DRY。

但这是本项目最有价值的一条设计：生成侧算错 → 线接不到端口 → 回读时体检报悬空；
解析侧算错 → 生成的文件被误读 → 仿真与 Logisim 对不上。两边同时错成一样几乎不可能。

实际抓到的 bug：`NAND` 反相圈少算 10px、`NOT` 不遵循加宽规律、子电路锚点不在左上角、
分线器 `b0` 的上下顺序。

代价：改端口公式要改两处。收益：不会带着系统性错误一路跑到交付。

## 3. 不用隧道

隧道能让布线成功率接近 100%，但：

- 多数课程作业明确禁止；
- 截图看不出真实连接，人工审阅等于失明；
- 标签写错时网络静默断开。

所以 `circ_build` 老老实实走导线，布线器用 10px 网格 A*，把元件体、所有端口、已有线段都当障碍。
布不通就报"网络 X 从 A 到 B 无解"，让你挪元件，而不是偷偷塞一个隧道。

## 4. `-w` 没有被包装成"时序验证"

`-w` 是 Logisim 自带能力，包一层就能跑，看起来很好用。但实测它每行都从初始状态重新求值：
两级触发器链的 `q1` 永远是 0。

所以文档里反复标注"只能验组合"，并用 `circ_sim` 补上真正的多拍仿真。
一个会给出假通过的验证器，比没有验证器更糟。

## 5. 触发器采样：逐拍、逐器件

第一版仿真器是"一拍内算完所有 D，再统一更新"，结果行波级联全错——它把异步当成了同步。

现在每拍内循环：逐个比较各触发器自己 `CLK` 的前后值，只有 0→1 才采样 `D`，然后重新收敛，
直到没有新的沿（上限 64 轮）。这样同步共用时钟、行波级联、混合结构都对。

## 6. 知识库单独存，且能自愈

几何事实和踩坑记录放在 `knowledge.json`，不在代码里写死：

- 位置可被 `LOGISIM_KB` 或 `${CODEBUDDY_PLUGIN_DATA}` 重定向，升级插件不丢用户积累；
- 首次运行从随包文件播种；
- 原子写（tmp + `os.replace`）；
- 文件损坏时备份为 `.corrupt` 再重建，不让一个坏文件拖死整条工具链。

## 7. 版本号只留一个来源

服务端启动时读 `plugin.json` 拿版本，而不是自己在代码里写一个常量。
`tools/check_release.py` 在 CI 里校验三处（清单 / 兜底默认值 / CHANGELOG）一致。

## 8. 平台细节写进 `.gitattributes`

- `.cmd` 必须 CRLF：LF 的批处理在某些情况下解析异常；
- `.cmd` 必须纯 ASCII：GBK 控制台下 UTF-8 中文注释会让 `rem` 行被当命令执行
  （实测错误信息：`'正常启动' 不是内部或外部命令`）；
- `where python` 会匹配当前目录下的同名文件，所以启动器里改用 `where python.exe`。

这些不是"风格问题"，是会让插件在别人机器上直接起不来的问题。
