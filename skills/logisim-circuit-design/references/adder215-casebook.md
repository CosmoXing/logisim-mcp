# 实验2 构建加法器（Logisim-ITA 2.15.0.2）实战复盘

一次真实交付：给定期末实验的「加法器验证电路.circ」4 个框架，补齐串行加法器链与快速加法器，
最终 7 个电路、5080 行向量 0 失败、全电路 `ERRCOUNT 0`。

## 1. 交付结构

```
加法器验证电路.circ
├─ 半加器                  XOR + AND
├─ 全加器                  2 × 半加器 + OR
├─ 4位全加器               4 × 全加器；A0~A3 / B0~B3 / C0 → S0~S3 / C4
├─ 并行进位器              74LS182：C1~C4、G*、P*（19 门，多输入与/或）
├─ 4并行加法器             P/G 生成 + 74182 + 4 个 S 异或
├─ 16位验证                4 × 4位快速加法器 + 第二级 74182
└─ 8位串行加法器验证电路   2 × 4位全加器 + B⊕Sub + Cin⊕Sub + 溢出
```

给定框架必须**原样保留**（Pin / Tunnel / Probe / Splitter / Text / 外观），新逻辑追加在
`</circuit>` 之前。整块替换会丢引脚，加载时报
`Appearance element circ-port not found`。

## 2. 关键语义（由框架文字推导，已实测）

- **Sub 控制**：`B' = B ⊕ Sub`，且最低位进位 `C0 = Cin ⊕ Sub`。
  这样正好满足框架上的四行说明：
  `Sub=0,Cin=0 → A+B`；`Sub=0,Cin=1 → A+B+1`；
  `Sub=1,Cin=0 → A-B`；`Sub=1,Cin=1 → A-B-1`。
- **溢出**：`OF = (A7 == B7') & (A7 != S7)`（B7' 是异或后的符号位），
  等价于 `C7 ⊕ C8`，不需要额外引出内部进位。
- **4位快速加法器端口**：`C4` 是最高位进位，`C3` 是次高位进位（框架文字原话），
  `G* / P*` 是组进位生成/传递。
- **16 位**：第二级 74182 的 `C1/C2/C3` 分别送 1/2/3 号 4 位块的 `C0`；
  `C16` 取最高块的 `C4`，`C15` 取最高块的 `C3`。

## 3. 2.15 实测几何（与 2.16/2.7.1 的差异）

| 项 | 2.15.0.2 |
|---|---|
| AND/OR 输入口 | `x-30` |
| XOR 输入口 | `x-40` |
| NOT 输入口 | `x-20` |
| 多输入排布 | 奇数 10px 均布；偶数中间留 20px 空档（4 输入 −20/−10/+10/+20） |

## 5. 本次踩到的坑（对应 pitfalls.md K 组）

1. 用 `.circ` 的 `source` 属性判断版本 → 误判。exe 与保存文件可能不是同一个。
2. 整块替换框架电路 → 外观端口找不到、文件打不开。
3. `circ271_check` 对 2.15 报“导线穿元件体”是固定误报（它按 x-50 建门体）。
4. `netcheck.py` 把 Probe 当 0 位宽 → 每个框架 6 处假冲突。
5. NOT 门输入口写成 `x-30` → 溢出逻辑输出 `E`。
6. 偶数输入门的 y 偏移按 10px 均布算 → 端口错位。
7. 自检把“线端落在实例端口”当穿体 → 需要放行该元件的端口点。
8. 向量列数 ≠ 表头列数 → 整表全 fail。
9. G*/P* 期望值从 LSB 累加 → 4 并行/16 位大面积失败，必须从 MSB 递推。
10. Launch4j 的 exe 不能直接喂探针，要按 `PK\x03\x04` 偏移切出内嵌 jar。
11. 加载失败时 GUI 对话框吞异常，用 `scripts/v215/LoadTest.java` 覆写 `Loader.showError`。

## 6. 延迟（报告可直接用）

- 4 位串行：每级 FA 约 3 个门延迟，C4 约 8~9 级。
- 4 位快速：`P/G` 1 级 → `C1~C4/G*/P*` 2 级 → `S` 再 1 级，共约 3~4 级。
- 16 位快速：块内 `P/G` 1 级 + 块 CLA 2 级 → 组 `G*/P*`；第二级 CLA 2 级 → 组进位；
  `S` 再 1 级，共约 5~6 级（串行约 32 级）。
