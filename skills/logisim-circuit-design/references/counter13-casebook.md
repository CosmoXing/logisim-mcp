# 案例复盘：两位十三进制计数器（模 169，5.0 环境）

这是一次真实交付的完整记录：从"能生成文件"到"Logisim 里真的能仿真"，中间踩了 13 个坑。
每个坑都写成 **现象 → 根因 → 解决 → 怎么验证**，方便直接套用到下一个电路。

> 环境：logisim-evolution **5.0.0**，纯门电路 + D 触发器，禁用内置计数器/寄存器/隧道。
> 交付物：`main`（时钟+数码管+LED）→ `CounterDue`（两片级联+溢出）→ `Counter13`（单个模 13 计数位）。

---

## 一、题目与设计（先有正确答案，再谈排错）

需求：两位十三进制，每位 0~C，显示 00→CC 共 169 个状态；计满 CC 停止并点亮 LED；
只能用触发器和门电路，不许用隧道。

**模 13 计数位（Counter13）**——用"二进制递增 + 归零掩码"，不要画 5 变量卡诺图：

```
T0 = EN
T1 = EN·Q0
T2 = T1·Q1
T3 = T2·Q2
S12 = Q3·Q2·~Q1·~Q0          # 本位 == 12(C)
M   = ~(EN·S12)              # 归零掩码
Di  = (Qi ⊕ Ti) · M
CARR = EN·S12
```

- EN=0 时 `Di = Qi`，整位保持；
- 数到 C 且 EN=1 时 `M=0`，四个 D 全 0，同时 `CARR=1`；
- 上电触发器全 0，自然从 0 开始。

**两位级联（CounterDue）**——同步级联，不要拿进位当时钟：

```
EN_L = ~(S12_L · S12_H)      # 到 CC 就冻结低位
EN_H = CARR_L                # 低位满 13 才让高位 +1
LED  = S12_L · S12_H
cp   → 两片共用
```

这个写法**没有反馈环**：`EN_L` 只依赖两个 S12，不依赖 CARR，所以不会振荡。

## 二、13 个坑（按"浪费的时间"排序）

### 坑 1：门输入口差了 30px（最贵的一个）

- **现象**：改好一处、另一处又坏；同一套布线逻辑在示例文件里能用，自己生成的就不通。
- **根因**：3.9 时代 `size=40`，门输入口在 `loc.x-20`；**5.0 默认 `size=50`，输入口在 `loc.x-50`**。
  带反相圈的再 +10（NAND/NOR/XNOR 在 −60），XOR 因曲线护盾也在 −60，XNOR 是 −70。
  照抄 3.9 的 `-20`，每个门的四根线全部悬空。
- **解决**：几何不要凭记忆，先查表：

  | 门 | 宽度 | 2 输入口 |
  |---|---|---|
  | AND / OR | 50 | (−50, ∓20) |
  | NAND / NOR | 60 | (−60, ∓20) |
  | XOR | 60 | (−60, ∓20) |
  | XNOR | 70 | (−70, ∓20) |
  | **NOT** | **30** | **(−30, 0)** |

- **验证**：`python tools/selftest.py` 里的 `circ_geometry` 用例；或直接跑一个 2 输入与门真值表。

### 坑 2：NOT 门不符合"反相圈 +10"规律

- **现象**：按 −50 / −60 接 NOT，两种都输出 `E`；换成 NAND 短接两输入就正常。
- **根因**：NOT 的画框是 `−30..−10`，宽度按 **30** 算，输入口在 **−30**。它既不是 50 也不是 60。
- **解决**：优先用 `NAND(a,a)` 或直接用触发器的 `~Q`；非用 NOT 不可时按 −30 接。
- **验证**：6 组偏移扫描（−20/−30/−40/−50/−60/−70）只有 −20 与 −30 连通，其余悬空。
  顺带发现 `WireRepair` 会把落在门包围盒内的线端吸附到输入口，所以 −20 也能"碰巧"通——**不要依赖吸附**。

### 坑 3：导线穿过元件端口 → 输出变 `E`

- **现象**：触发器输入正常、时钟正常，`Q` 却是 `E`；体检也说不清哪根线的问题。
- **根因**：触发器 `Q(0,0)` 与 `~Q(0,20)` 只隔 20px。一根从右侧竖直穿过去的线同时压到两个输出口，等于把 `Q` 和 `~Q` 短接。
- **解决**：布线器必须把**所有元件端口**列为禁入点（不只是元件体）。走线绕行 10~20px 即可。
- **验证**：`circ_audit` 的 `conflict` 字段会直接点名；真值表里表现为整列 `E`。

### 坑 4：同网共线合并，把端点变成内点（最隐蔽）

- **现象**：`Q0` 网络从触发器出来后接了三处分叉，探针显示"pin 侧有电、分配侧没电"。
- **根因**：`(680,140)→(690,140)` 与 `(690,140)→(730,140)` 共线相接，Logisim 加载时把它**合并成一根 (680~730,140) 的长线**，
  原来的端点 `(690,140)` 变成内点。于是它与竖井的关系从"端点搭接"退化成"内点×内点交叉"——**不导通**。
- **解决**：
  1. 分支不要挂在另一根线的端点延长线上，错开 10px 走 T 型搭接；
  2. 布线校验器要**先做共线合并，再判连通**，否则会误判"已连通"。
- **验证**：这个坑是靠"40 个端口探针普查"定位的——只有一个网络全 `U`，其余全通，故障点唯一。

### 坑 5：同网"内点×内点"纯交叉不导通

- **现象**：两条线明明同属一个网络，十字交叉处却像断了一样。
- **根因**：Logisim 只认"端点落在别人身上"。交点对双方都是内点时不算连接。
- **解决**：需要连接就在交点引出一段短线（端点落在交点）；不需要连接就绕开，别贴着走。
- **验证**：W 系列对照实验（角接 / 内 T / 纯交叉 / 端点压线 四种形状各做一条链）。

### 坑 6：`-w` 测试向量根本不能验时序（假通过来源）

- **现象**：346 行向量的时序测试"0 失配"，但电路在 GUI 里打开是错的。
- **根因**：`-w` **每一行都从初始状态重新求值**。两级 D 触发器链的 `q1` 永远传不过去。
- **解决**：时序用自写网表仿真（逐拍推进、逐触发器检测各自 `CLK` 的 0→1 沿）；
  `-w` 只用来验组合逻辑。**报告"通过"之前先确认它真的执行了向量**（列名对不上时会静默跳过）。
- **验证**：两级 DFF 链交替时钟实验，`q1` 恒 0 → 定性结论。

### 坑 7：触发器初值 `U` 会沿组合环自锁（清零失败的真正原因）

- **现象**：想尽办法清零——接 `R` 端、加同步清零门、上电拉低——仿真里始终 `UUUU`。
- **根因**：`-w` 模式下触发器初态是未知 `U`；与门压不住 `U`（`U AND 0 = 0` 成立，但 `U AND 1 = U`），
  于是 `U` 在 `Q → D` 的回路里自我维持。**同步清零对 `U` 无效**。
- **解决**：
  - 仿真用自写内核，触发器初值固定 0；
  - 真机用 `Ctrl+R`（电路复位）或让用户手动点复位；
  - **不要**为了清零去接 `R` 端再走一条长线——`R(-10,30)` 与 `S(-30,30)` 相邻，
    横穿的线很容易同时命中 `R` 和 `S`，得到非法状态、仿真挂死。
- **验证**：这也是为什么最后删掉了全部 `R0~R3` 引脚，Counter13 只剩 `EN / cp / Q / CARR / S12` 五口。

### 坑 8：子电路实例端口不是 `(X+50, Y+60+10i)`

- **现象**：两片 Counter13 摆在 main 里，所有连线都"画到了"，但 `OH/OL` 全是 `U`。
- **根因**：`DefaultClassicAppearance` 的真实规则是 **按 facing 分边 + 10px 间距 + 锚点落在东边第一个口**。
  8 个引脚时，6 个输入会被压进 50px 高度，端口间距只有 10px。
- **解决**：
  1. 端口公式：东 `(X, Y+10j)`，西 `(X-30, Y + offsetW - offsetE + 10i)`；
  2. 更根本的办法是**砍引脚**：把 8 口降到 5 口（去掉 4 个复位脚），端口从"挤成一团"变成"两三种可能"。
- **验证**：做 1 入 3 出 / 2 入 3 出 / 6 入 2 出 三个直通子电路，各跑 2 行向量，端口全中才算公式对。

### 坑 9：布线器把元件体当障碍，却没把端口当障碍

- **现象**：`M` 网络沿 `x=760` 上行，正好从四个与门的门体里穿过去，四个 `D` 全变 `E`。
- **根因**：障碍图只登记了"元件包围盒"，而 `free()` 里查的是像素坐标、集合里存的是网格坐标，单位不一致，等于没拦住。
- **解决**：坐标统一到网格单位再比较；端口集合单独维护一份。
- **验证**：给出"网络 X 在 (760,300) 穿过 mask0 包围盒"这种能直接改的报错，而不是只报一个 `E`。

### 坑 10：分线器方向是猜的

- **现象**：同一个分线器，有时当合并用正常，有时输出全 `U`。
- **根因**：分线器既可拆也可合，方向取决于哪一侧有驱动。仿真器若写死一种，另一半场景就错。
- **解决**：**静态判定**——位侧有外部驱动 → 合并；否则总线侧有驱动 → 拆分。
- **验证**：4 位分别单独驱动，看总线值是否等于 `1<<i`（同时确认 `b0` 在最上）。

### 坑 11：仿真器按"同一拍统一采样"，行波级联全错

- **现象**：两级 DFF 级联，`q1` 跟着 `q0` 一起翻，时序完全不对。
- **根因**：一拍内先算完所有 D 再统一更新，等于把异步级联当成同步。
- **解决**：一拍内循环——逐个比较各自 `CLK` 前后值，只有 0→1 才采样 `D`，然后重新收敛；直到没有新的沿为止（最多 64 轮）。
- **验证**：异步 2 位计数器 `00→01→10→11→00`；同步计数器则共用 `cp`。

### 坑 12：一个写反的三元表达式，把整条总线网漏掉了

- **现象**：`Q` 输出恒 `UUUU`，但内部计数明明在动（`CARR` 列 50/54 通过）。
- **根因**：`nets_with()` 里 `("cp","bus") if mirror else ("cp","bus")` —— 两个分支一样，`bus` 在**所有**构建里都被剔除。
  分线器没有总线可接，`Q` 引脚自然悬空。
- **解决**：镜像/正式两套网络集合要显式列出差异键，并写一条断言（"正式构建必须包含 bus 网"）。
- **验证**：`-t table` 里 `Q` 列全 `U` 而 `CARR` 正常，就是"内部对、出口断"的指纹。

### 坑 13：布局重叠与数码管位宽

- **现象**：自动布局把 CLOCK 和 AND 放在同一个坐标；数码管显示乱码。
- **根因**：特殊元件（时钟/LED/数码管）没有包围盒，撞坐标检测形同虚设；数码管数据口固定 4 位。
- **解决**：分列布局（时钟最左、门按依赖深度、LED/数码管最右），撞坐标自动下移；4 根线先经分线器合并成总线再进数码管。
- **验证**：`body_overlap` 为空；数码管显示 `0~F` 正确。

## 三、最终验证矩阵（"敢说通过"的依据）

| 层 | 方法 | 结果 |
|---|---|---|
| Counter13 次态组合逻辑 | 4 个触发器换成 4 组输入引脚做**组合镜像**，交给 Logisim 自己跑 32 行向量 | 32/32 通过 |
| Counter13 时序 | 自写网表仿真 15 拍 + `EN=0` 保持 | 0→1→…→12→0，CARR 正确 |
| 整机全序列 | 自写网表仿真 **172 拍**（169 状态 + 溢出后 3 拍） | 00→…→CC 逐拍正确，CC 起 LED=1 且冻结 |
| 上电状态 | Logisim `-t table` | OH=0、OL=0、LED=0，无 `E` |
| 静态连接 | `circ_audit` | 69 网 / 178 端口，0 悬空 0 冲突 0 孤立 |

**关键方法论**：组合部分用 Logisim 自己验（把触发器换成引脚做镜像），时序部分用自写内核验，
两套几何独立实现、互为交叉校验。这样任何一边算错都会在对账时暴露，而不是靠"看起来对"。

## 四、下次可以直接照抄的排查顺序

```
电路"不对"（E / U / 不计数 / 显示乱）
│
├─ 1. 静态体检：有 conflict 吗？
│     └─ 有 → 先解决短路。九成是导线穿过端口，或两个输出接同一网络。
│
├─ 2. 输出是 E 还是 U？
│     ├─ E  → 冲突/短路/位宽不符
│     └─ U  → 该网络没有驱动：端点没落在端口上、共线合并把端点变内点、或整条网在生成时被漏掉
│
├─ 3. 内部计数在动吗？（看 CARR / 中间探针）
│     ├─ 在动但出口恒 U → 是"出口读出路径"断了（分线器/总线/输出引脚）
│     └─ 完全不动      → 是时钟没到、或 EN 恒 0
│
├─ 4. 仿真对、Logisim 不对？
│     └─ 几何/连线问题，不是逻辑问题 → 查端口偏移（尤其门 −50/−60、NOT −30）
│
└─ 5. 逻辑就不对？
      └─ 用组合镜像 + 32 行真值表定位到具体某一位的 D 表达式
```

## 五、五条硬结论（写进肌肉记忆）

1. **先确认 Logisim 版本**，再决定端口坐标。3.9 的 `-20` 和 5.0 的 `-50` 差 30px，抄错就是一下午。
2. **端口是禁入点**，不是只有元件体是。
3. **同网共线会合并**，合并后要重新判连通——这是"看着接上了其实断了"的唯一来源。
4. **`-w` 只验组合**；时序必须多拍仿真，且触发器初值要可控。
5. **子电路引脚越少越好**。8 口挤 50px 不是"难布"，是"布不通"。能砍的复位/使能脚全砍掉。
