# 实战坑表（38 条，症状 → 根因 → 解决）

按「从文件到电路、从布局到运行环境」排序。每条都是踩过的，不是推测。
G 组是 5.0 环境做 13 进制计数器时新增的，完整上下文见 `counter13-casebook.md`。

---

## A. 文件与格式

### A1 打开报「加载电路文件出错」
- **根因**：同目录有 `.xxx.circ.autosave`（异常退出留下的恢复文件），启动时尝试恢复并失败。
- **定位**：把 `.circ` 复制成新名字，能打开 → 就是 autosave 的锅。
- **解决**：删掉 autosave。生成/重写 `.circ` 前后都检查一遍。

### A2 打开后没有绘图工具条，以为是软件装坏了
- **根因**：toolbar 配置是**逐文件保存**的。脚本生成的文件只有 `<options/>`，没有 `<toolbar>`，所以没有工具条；而「新建工程」用的是模板 `default.templ`，自带工具条。
- **定位**：`grep -c "<toolbar>" x.circ` 为 0。
- **解决**：在 `<project>` 下补 toolbar 块（不是塞进 `<options>`），`<tool>` 必须带 `lib="8"`。生成器 `project()` 已内置。

### A3 元件莫名消失，整条网络变 `E`
- **根因**：组件名写错（典型：把 `Hex Digit Display` 写成 `HexDigit`）。Logisim 静默丢弃无法识别的组件，不报错。
- **解决**：核对组件名；数码管是 `"Hex Digit Display"`，lib `5`。
- **预防**：新组件先在 GUI 里放一个并保存，读回文件照抄 lib 数字和名字。

### A4 3.9 的老文件在 5.0 下端口错位
- **根因**：老写法 `<a name="output" val="true"/>` 在 5.0 的子电路外观计算里不可靠。
- **解决**：一律改写成 `<a name="type" val="input|output"/>`。

## B. 坐标与端口

### B1 子电路端口怎么算都不对
- **根因**：以为 y 间距是 20 或 30。实测是 **10**：输入 `(loc.x-30, loc.y+10i)`，输出 `(loc.x, loc.y+10j)`，框宽恒 30。
- **定位**：先用 3 入 2 出的最小模块验证一遍坐标，再放大到实际模块。
- **解决**：照几何常量写，不要「估算」。

### B2 模块引脚全 `U`，探针怎么点都没反应
- **根因**：模块端口太多。实测 9 入 5 出的实例端口位置全错；同一套代码 3 入 2 出完全正常。
- **解决**：把大模块拆成多个 ≤3 入 / ≤2 出的模块串起来（例如 4 位 BCD 加法器 = 4 个「3 入 2 出」的位模块串行进位）。
- **预防**：任何超过 3 个输入的模块，先怀疑它。

### B3 导线画过去了但没连上
- **根因**：终点差 10px。端口是像素级精确匹配。
- **解决**：终点写成 `(loc.x-30, loc.y+10i)` 这样的表达式，不要手填近似值。

### B4 Logisim 卡死 / OutOfMemoryError
- **根因**：导线**穿过**子电路端口（或画斜线穿过 / 布线失败留下断头线），触发 `WireRepair.doOverlaps` 死循环。栈顶固定是 `WireRepair.lambda$doOverlaps$0`。
- **解决**：走线绕开端口；布线前把端口登记为障碍点（`router.add_obstacle`）。
- **铁律**：布线器返回 `None`（有网络没布通）时**绝对不要写出文件**。`G.check(fails)` 会在写盘前抛异常，把问题拦在生成阶段。

### B5 门电路全接反了
- **根因**：以为 `loc` 是门中心或输入口。实际 `loc` 是**输出口**，输入口在 `(loc.x-20, loc.y±20)`。
- **解决**：入线终点统一画到 `loc.x-10`（跨越所有门型的输入端口，XOR 更宽也够）。

## C. 位宽与总线

### C1 橙色「位宽不兼容」，输出全 `E`
- **根因**：位宽不匹配。最常见的是 `cout` 直接接数码管——数码管数据口**固定 4 位**，`width="1"` 不生效。
- **解决**：4 路分线器当合并器，`bit0` 接 `cout`，`bit1..3` 接 `Ground`，合并口出 4 位总线再进数码管。
- **定位手法**：把可疑的数码管删掉做对照文件，提示消失 → 就是它。

### C2 合并总线后数值错位
- **根因**：分线器反向当合并器时，位序是 `o = i3 i2 i1 i0`（最上面的输入是最高位）。
- **解决**：从下往上接线时记得反过来；或者显式用 `bits=[...]` 指定映射。

### C3 分线器短接
- **根因**：`bit2` 的分线口与合并口**同高**（都在 `loc.y`），从左侧接入会穿过合并口。
- **解决**：`bit2` 从**右侧**绕入。

### C4 16 位拆分接不出来
- **根因**：`fanout=16` 时端口不按 10px 排列，`b10` 以上取不到。
- **解决**：拆成多个 4 位分线器，或每位一个 4 位引脚。

## D. 布局与可读性

### D1 展开子电路，电路贴在画布左上角，左边引脚看不见
- **根因**：元件从 `(0,0)` 开始画，输入引脚标签画在左侧，被面板挡住。
- **解决**：整体平移 `translate(+120,+60)`；生成器里留常量 `OX/OY`。
- **验证**：平移后重跑测试向量，仍然 7/7 说明端口偏移没变（平移是安全的）。

### D2 打开只有 0.15 倍缩放，什么都看不清
- **根因**：子电路内部尺寸过大（例如为自动布线留通道，撑到 3400×5500）。
- **解决**：压到 2000×1600 内。手段：行距 1100→340、整体右移给标签腾位置、删掉横穿全图的长总线、把远端逻辑搬到源旁边。
- **预防**：布线前就规划行距（模块高 60 + 通道 100 ⇒ 行距 150~340）。

### D3 截图每次都不一样，拼图对不齐
- **根因**：缩放设为「自动」，窗口大小一变比例就变。
- **解决**：固定 ×1（或 ×2）再截；顶层和子电路各自定一次，全程不改。

### D4 `PrintWindow` 截不到菜单和缩放按钮的变化
- **解决**：用 `PIL.ImageGrab.grab()` 全屏截图再按窗口坐标裁剪。截之前把窗口置前。

## E. 运行环境

### E1 `-Djava.awt.headless=true` 时 `-w` 崩
- **根因**：`-w` 内部 `new Frame`。
- **解决**：只对纯文本模式（`-t`）允许 headless；`-w` 必须保留 GUI 环境。

### E2 工具里启动的 Logisim 窗口一闪就没
- **根因**：命令结束后子进程被回收，看着像崩溃。
- **解决**：用后台常驻方式启动（`run_in_background`）；不要用「启动后立即退出」的写法判断软件是否正常。

### E3 标题栏显示「未保存」
- **根因**：文件在打开期间被外部脚本改写，Logisim 检测到状态不一致。
- **解决**：关掉重开。**不要点保存**，否则用旧内存覆盖新文件。

### E4 命令行输出全是乱码
- **根因**：Windows 中文控制台 GBK 编码。
- **解决**：`| iconv -f gbk -t utf-8`，或在 Python 里按 gbk 解码（`verify.py` 已处理）。

### E5 用户说找不到「戳工具」
- **事实**：中文界面里 Poke Tool 叫 **手形工具**（工具条第一个手指图标）。不是 bug，是翻译。

## F. 方法论

### F1 一开始全靠隧道连线，作业直接不合格
- **教训**：隧道省事，但多数作业明令禁止，且截图看不出真实结构。
- **正确做法**：写一个通道布线器（正交、避让、禁止共线重叠），一次投入长期受益。见 `scripts/router.py`。

### F2 只在顶层验证，错了不知道错在哪
- **教训**：分层电路必须**每层单独验**。全加器 8/8 → 1 位 BCD 200/200 → 顶层 7/7，逐层收敛。
- **数字**：跳过分层验证时，定位一个进位错误平均要重画整张图；分层验证后每个 bug 都能定位到具体模块。

### F3 误判「这个版本没有工具栏」
- **教训**：功能不存在 ≠ 配置缺失。先 `grep` 文件里有没有对应配置块，再下结论。当时查了菜单也问了用户，其实只是生成的 `.circ` 缺 `<toolbar>`。

### F4 把「显示」和「验证」混在一个文件里
- **教训**：数码管会掩盖接线错误（看起来有数字就行），而且位宽限制多。拆成 `demo.circ`（展示）和 `demo_test.circ`（输出引脚验证）两份，由同一函数生成。

## G. 5.0 专属（做 13 进制计数器时新增）

### G1 门输入口在 `loc.x-50`，不是 `-20`
- **症状**：改好一处、另一处又坏；同一套布线逻辑在示例文件里能用，自己生成的就不通。
- **根因**：3.9 的 `size=40` → 输入口 `-20`；5.0 默认 `size=50` → `-50`。带反相圈、XOR 的曲线护盾再 +10。
- **解决**：按门型查表：AND/OR −50、NAND/NOR/XOR −60、XNOR −70、**NOT −30（特例，宽度 30）**。
- **验证**：`grep source` 确认版本；跑一个 2 输入与门真值表。

### G2 竖线穿过触发器右侧 → `Q` 与 `~Q` 短接
- **症状**：输入都正常，`Q` 恒 `E`；其余位正常。
- **根因**：`Q(0,0)` 与 `~Q(0,20)` 只隔 20px，一根竖直穿过的线同时压住两个输出口。
- **解决**：布线器的"禁入点"要包含**所有元件端口**，不能只有元件包围盒。
- **验证**：静态体检的 `conflict` 会点名；真值表整列 `E`。

### G3 同网共线相接被合并，端点变内点 → 分支失效
- **症状**：同一条网络，pin 侧有电、分配侧没电；探针说不清哪根断。
- **根因**：`(680,140)→(690,140)` 与 `(690,140)→(730,140)` 共线，加载时合并成长线，`(690,140)` 从端点变内点，
  与竖井的关系退化为"内点×内点交叉" → 不导通。
- **解决**：分支错开 10px 走 T 型搭接；校验器要**先合并共线再判连通**。
- **验证**：40 个端口探针普查，只有一条网全 `U`，故障点唯一。

### G4 同网"内点×内点"纯交叉不导通
- **症状**：明明同属一个网络，十字交叉处却像断的。
- **根因**：Logisim 只认"端点落在别人身上"。
- **解决**：要连接就从交点引一段短线；不连接就绕开。
- **验证**：角接 / 内 T / 纯交叉 / 端点压线 四种形状各做一条链，用真值表分辨。

### G5 `-w` 每行重置 → 时序"0 失配"是假通过
- **症状**：346 行向量 0 失配，打开 GUI 却是错的。
- **根因**：`-w` 每行都从初始状态求值。两级 DFF 链的 `q1` 永远传不过去。
- **解决**：时序改用多拍网表仿真（逐拍推进、逐触发器检测各自 `CLK` 的 0→1 沿）；
  `-w` 只验组合。**且要确认它真的执行了**——列名对不上时输出里根本没有 `expected` 行。
- **验证**：两级 DFF 交替时钟实验。

### G6 触发器初值 `U` 会沿组合环自锁
- **症状**：怎么都清不掉，始终 `UUUU`。
- **根因**：测试模式初态是 `U`；`U AND 1 = U`，`U` 在 `Q→D` 回路里自我维持。同步清零门压不住 `U`。
- **解决**：仿真内核把触发器初值置 0；真机用 `Ctrl+R`。**不要**为了清零接 `R` 端再走长线——
  `R(-10,30)` 与 `S(-30,30)` 相邻，横穿的线很容易同时命中两者，得到非法状态、仿真挂死。
- **验证**：把 `R0~R3` 全部删掉后，Counter13 只剩 5 个端口，问题随之消失。

### G7 子电路实例端口公式算错，整层连线全悬空
- **症状**：两片子电路摆在顶层，线都"画到了"，输出全 `U`。
- **根因**：按 `(X+50, Y+60+10i)` 算。真实规则是按 facing 分边、10px 间距、锚点落在东边第一个口。
- **解决**：用 `geometry.md` 第 4 节的表格；更根本的是把引脚砍到 3 入 2 出以内。
- **验证**：1 入 3 出 / 2 入 3 出 / 6 入 2 出 三个直通子电路，各跑 2 行向量，端口全中才算对。

### G8 仿真器按"同一拍统一采样"，行波级联全错
- **症状**：两级 DFF，`q1` 跟着 `q0` 一起翻。
- **根因**：一拍内先算完所有 D 再统一更新，等于把异步级联当同步。
- **解决**：一拍内循环——逐个比较各自 `CLK` 前后值，0→1 才采样 `D`，重新收敛，直到没有新的沿（上限 64 轮）。
- **验证**：异步 2 位计数器 `00→01→10→11→00`。

### G9 生成器里一个写反的三元表达式，把总线网整体漏掉
- **症状**：`Q` 恒 `UUUU`，但内部计数明明在动（`CARR` 正常）。
- **根因**：`("cp","bus") if mirror else ("cp","bus")` 两个分支一样，`bus` 在所有构建里都被剔除。
- **解决**：两套网络集合显式列差异键，并加断言"正式构建必须包含 bus 网"。
- **验证**：`Q` 全 `U` 而 `CARR` 正常 = "内部对、出口断"的指纹。

### G10 生成的文件 Logisim 不认引脚（类型写成 `in` / `out`）
- **症状**：文件能打开，但引脚没有箭头、网络全 `U`，体检报一堆"孤立端口"。
- **根因**：5.0 只认 `<a name="type" val="input"/>` 或 `val="output"`；写成 `in` / `out` 会被当成无类型引脚。
- **解决**：用 `circ_build` 生成（它写对），手改 XML 时注意这一条。
- **验证**：`circ_audit` 的 `dangling` 会立刻爆出来。

### G11 NOT 门接不通
- **症状**：按 −50 / −60 接 NOT，两种都输出 `E`。
- **根因**：NOT 的画框是 −30..−10，宽度按 **30** 算，输入口在 **−30**，不符合"反相圈 +10"的规律。
- **解决**：优先用 `NAND(a,a)` 或直接取触发器的 `~Q`；非用不可时按 −30 接。
- **验证**：6 组偏移扫描只有 −20/−30 连通（−20 是靠 `WireRepair` 吸附，别依赖）。

### G12 真值表跑到一半卡死 / 爆内存
- **症状**：`-t table` 长时间无响应。
- **根因**：n 个输入 = 2ⁿ 行。12 个输入 4096 行，16 个输入 65536 行。
- **解决**：`circuit_truth_table` 已内置保护——输入 >16 直接拒绝，行数默认截断 4096（`max_rows` 可调）。
  验大电路用 `circ_sim` 抽样，或把无关引脚去掉再验。
- **验证**：给一个 20 输入的空电路，应当直接返回拒绝信息而不是卡住。
