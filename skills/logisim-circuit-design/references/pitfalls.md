## A. 文件与格式

### A1 打开报「加载电路文件出错」
- 根因：同目录有 `.xxx.circ.autosave`（异常退出留下的恢复文件），启动时尝试恢复并失败。
- 定位：把 `.circ` 复制成新名字，能打开 → 就是 autosave 的锅。
- 解决：删掉 autosave。生成/重写 `.circ` 前后都检查一遍。

### A2 打开后没有绘图工具条，以为是软件装坏了
- 根因：toolbar 配置是逐文件保存的。脚本生成的文件只有 `<options/>`，没有 `<toolbar>`，所以没有工具条；而「新建工程」用的是模板 `default.templ`，自带工具条。
- 定位：`grep -c "<toolbar>" x.circ` 为 0。
- 解决：在 `<project>` 下补 toolbar 块（不是塞进 `<options>`），`<tool>` 必须带 `lib="8"`。生成器 `project()` 已内置。

### A3 元件莫名消失，整条网络变 `E`
- 根因：组件名写错（典型：把 `Hex Digit Display` 写成 `HexDigit`）。Logisim 静默丢弃无法识别的组件，不报错。
- 解决：核对组件名；数码管是 `"Hex Digit Display"`，lib `5`。
- 预防：新组件先在 GUI 里放一个并保存，读回文件照抄 lib 数字和名字。

### A4 3.9 的老文件在 5.0 下端口错位
- 根因：老写法 `<a name="output" val="true"/>` 在 5.0 的子电路外观计算里不可靠。
- 解决：一律改写成 `<a name="type" val="input|output"/>`。

## B. 坐标与端口

### B1 子电路端口怎么算都不对
- 根因：以为 y 间距是 20 或 30。实测是 10：输入 `(loc.x-30, loc.y+10i)`，输出 `(loc.x, loc.y+10j)`，框宽恒 30。
- 定位：先用 3 入 2 出的最小模块验证一遍坐标，再放大到实际模块。
- 解决：照几何常量写，不要「估算」。

### B2 模块引脚全 `U`，探针怎么点都没反应
- 根因：模块端口太多。实测 9 入 5 出的实例端口位置全错；同一套代码 3 入 2 出完全正常。
- 解决：把大模块拆成多个 ≤3 入 / ≤2 出的模块串起来（例如 4 位 BCD 加法器 = 4 个「3 入 2 出」的位模块串行进位）。
- 预防：任何超过 3 个输入的模块，先怀疑它。

### B3 导线画过去了但没连上
- 根因：终点差 10px。端口是像素级精确匹配。
- 解决：终点写成 `(loc.x-30, loc.y+10i)` 这样的表达式，不要手填近似值。

### B4 Logisim 卡死 / OutOfMemoryError
- 根因：导线穿过子电路端口（或画斜线穿过 / 布线失败留下断头线），触发 `WireRepair.doOverlaps` 死循环。栈顶固定是 `WireRepair.lambda$doOverlaps$0`。
- 解决：走线绕开端口；布线前把端口登记为障碍点（`router.add_obstacle`）。
- 铁律：布线器返回 `None`（有网络没布通）时绝对不要写出文件。`G.check(fails)` 会在写盘前抛异常，把问题拦在生成阶段。

### B5 门电路全接反了
- 根因：以为 `loc` 是门中心或输入口。实际 `loc` 是输出口，输入口在 `(loc.x-20, loc.y±20)`。
- 解决：入线终点统一画到 `loc.x-10`（跨越所有门型的输入端口，XOR 更宽也够）。

## C. 位宽与总线

### C1 橙色「位宽不兼容」，输出全 `E`
- 根因：位宽不匹配。最常见的是 `cout` 直接接数码管——数码管数据口固定 4 位，`width="1"` 不生效。
- 解决：4 路分线器当合并器，`bit0` 接 `cout`，`bit1..3` 接 `Ground`，合并口出 4 位总线再进数码管。
- 定位手法：把可疑的数码管删掉做对照文件，提示消失 → 就是它。

### C2 合并总线后数值错位
- 根因：分线器反向当合并器时，位序是 `o = i3 i2 i1 i0`（最上面的输入是最高位）。
- 解决：从下往上接线时记得反过来；或者显式用 `bits=[...]` 指定映射。

### C3 分线器短接
- 根因：`bit2` 的分线口与合并口同高（都在 `loc.y`），从左侧接入会穿过合并口。
- 解决：`bit2` 从右侧绕入。

### C4 16 位拆分接不出来
- 根因：`fanout=16` 时端口不按 10px 排列，`b10` 以上取不到。
- 解决：拆成多个 4 位分线器，或每位一个 4 位引脚。

## D. 布局与可读性

### D1 展开子电路，电路贴在画布左上角，左边引脚看不见
- 根因：元件从 `(0,0)` 开始画，输入引脚标签画在左侧，被面板挡住。
- 解决：整体平移 `translate(+120,+60)`；生成器里留常量 `OX/OY`。
- 验证：平移后重跑测试向量，仍然 7/7 说明端口偏移没变（平移是安全的）。

### D2 打开只有 0.15 倍缩放，什么都看不清
- 根因：子电路内部尺寸过大（例如为自动布线留通道，撑到 3400×5500）。
- 解决：压到 2000×1600 内。手段：行距 1100→340、整体右移给标签腾位置、删掉横穿全图的长总线、把远端逻辑搬到源旁边。
- 预防：布线前就规划行距（模块高 60 + 通道 100 ⇒ 行距 150~340）。

### D3 截图每次都不一样，拼图对不齐
- 根因：缩放设为「自动」，窗口大小一变比例就变。
- 解决：固定 ×1（或 ×2）再截；顶层和子电路各自定一次，全程不改。

### D4 `PrintWindow` 截不到菜单和缩放按钮的变化
- 解决：用 `PIL.ImageGrab.grab()` 全屏截图再按窗口坐标裁剪。截之前把窗口置前。

## E. 运行环境

### E1 `-Djava.awt.headless=true` 时 `-w` 崩
- 根因：`-w` 内部 `new Frame`。
- 解决：只对纯文本模式（`-t`）允许 headless；`-w` 必须保留 GUI 环境。

### E2 工具里启动的 Logisim 窗口一闪就没
- 根因：命令结束后子进程被回收，看着像崩溃。
- 解决：用后台常驻方式启动（`run_in_background`）；不要用「启动后立即退出」的写法判断软件是否正常。

### E3 标题栏显示「未保存」
- 根因：文件在打开期间被外部脚本改写，Logisim 检测到状态不一致。
- 解决：关掉重开。不要点保存，否则用旧内存覆盖新文件。

### E4 命令行输出全是乱码
- 根因：Windows 中文控制台 GBK 编码。
- 解决：`| iconv -f gbk -t utf-8`，或在 Python 里按 gbk 解码（`verify.py` 已处理）。

### E5 用户说找不到「戳工具」
- 事实：中文界面里 Poke Tool 叫 手形工具（工具条第一个手指图标）。不是 bug，是翻译。

## F. 方法论

### F1 一开始全靠隧道连线，作业直接不合格
- 教训：隧道省事，但多数作业明令禁止，且截图看不出真实结构。
- 正确做法：写一个通道布线器（正交、避让、禁止共线重叠），一次投入长期受益。见 `scripts/router.py`。

### F2 只在顶层验证，错了不知道错在哪
- 教训：分层电路必须每层单独验。全加器 8/8 → 1 位 BCD 200/200 → 顶层 7/7，逐层收敛。
- 数字：跳过分层验证时，定位一个进位错误平均要重画整张图；分层验证后每个 bug 都能定位到具体模块。

### F3 误判「这个版本没有工具栏」
- 教训：功能不存在 ≠ 配置缺失。先 `grep` 文件里有没有对应配置块，再下结论。当时查了菜单也问了用户，其实只是生成的 `.circ` 缺 `<toolbar>`。

### F4 把「显示」和「验证」混在一个文件里
- 教训：数码管会掩盖接线错误（看起来有数字就行），而且位宽限制多。拆成 `demo.circ`（展示）和 `demo_test.circ`（输出引脚验证）两份，由同一函数生成。

## G. 5.0 专属（做 13 进制计数器时新增）

### G1 门输入口在 `loc.x-50`，不是 `-20`
- 症状：改好一处、另一处又坏；同一套布线逻辑在示例文件里能用，自己生成的就不通。
- 根因：3.9 的 `size=40` → 输入口 `-20`；5.0 默认 `size=50` → `-50`。带反相圈、XOR 的曲线护盾再 +10。
- 解决：按门型查表：AND/OR −50、NAND/NOR/XOR −60、XNOR −70、NOT −30（特例，宽度 30）。
- 验证：`grep source` 确认版本；跑一个 2 输入与门真值表。

### G2 竖线穿过触发器右侧 → `Q` 与 `~Q` 短接
- 症状：输入都正常，`Q` 恒 `E`；其余位正常。
- 根因：`Q(0,0)` 与 `~Q(0,20)` 只隔 20px，一根竖直穿过的线同时压住两个输出口。
- 解决：布线器的"禁入点"要包含所有元件端口，不能只有元件包围盒。
- 验证：静态体检的 `conflict` 会点名；真值表整列 `E`。

### G3 同网共线相接被合并，端点变内点 → 分支失效
- 症状：同一条网络，pin 侧有电、分配侧没电；探针说不清哪根断。
- 根因：`(680,140)→(690,140)` 与 `(690,140)→(730,140)` 共线，加载时合并成长线，`(690,140)` 从端点变内点，
  与竖井的关系退化为"内点×内点交叉" → 不导通。
- 解决：分支错开 10px 走 T 型搭接；校验器要先合并共线再判连通。
- 验证：40 个端口探针普查，只有一条网全 `U`，故障点唯一。

### G4 同网"内点×内点"纯交叉不导通
- 症状：明明同属一个网络，十字交叉处却像断的。
- 根因：Logisim 只认"端点落在别人身上"。
- 解决：要连接就从交点引一段短线；不连接就绕开。
- 验证：角接 / 内 T / 纯交叉 / 端点压线 四种形状各做一条链，用真值表分辨。

### G5 `-w` 默认每行重置 → 时序"0 失配"是假通过
- 症状：346 行向量 0 失配，打开 GUI 却是错的。
- 根因：`-w` 不加特殊列时每行都从初始状态求值。两级 DFF 链的 `q1` 永远传不过去。
- 解决（8 位乘法器项目实测修正）：表头加 `<set>` `<seq>` 两列，`-w` 就变成真正的时序测试——
  按 `set` 分组、组内按 `seq` 递增执行并保留电路状态。`clk` 写普通 0/1 列，靠 0→1 那行产生上升沿。
  期望值逐行写全，无关位写 `<DC>`，高阻写 `<float>`。示例见 `SKILL.md` 第 6 节。
  且要确认它真的执行了——列数对不上时 Logisim 静默跳过整行、仍报「通过」，见 H7。
- 验证：两级 DFF 交替时钟实验；故意写错一行期望确认它报 `失败：1`。

### G6 触发器初值 `U` 会沿组合环自锁
- 症状：怎么都清不掉，始终 `UUUU`。
- 根因：测试模式初态是 `U`；`U AND 1 = U`，`U` 在 `Q→D` 回路里自我维持。同步清零门压不住 `U`。
- 解决：仿真内核把触发器初值置 0；真机用 `Ctrl+R`。不要为了清零接 `R` 端再走长线——
  `R(-10,30)` 与 `S(-30,30)` 相邻，横穿的线很容易同时命中两者，得到非法状态、仿真挂死。
- 验证：把 `R0~R3` 全部删掉后，Counter13 只剩 5 个端口，问题随之消失。

### G7 子电路实例端口公式算错，整层连线全悬空
- 症状：两片子电路摆在顶层，线都"画到了"，输出全 `U`。
- 根因：按 `(X+50, Y+60+10i)` 算。真实规则是按 facing 分边、10px 间距、锚点落在东边第一个口。
- 解决：用 `geometry.md` 第 4 节的表格；更根本的是把引脚砍到 3 入 2 出以内。
- 验证：1 入 3 出 / 2 入 3 出 / 6 入 2 出 三个直通子电路，各跑 2 行向量，端口全中才算对。

### G8 仿真器按"同一拍统一采样"，行波级联全错
- 症状：两级 DFF，`q1` 跟着 `q0` 一起翻。
- 根因：一拍内先算完所有 D 再统一更新，等于把异步级联当同步。
- 解决：一拍内循环——逐个比较各自 `CLK` 前后值，0→1 才采样 `D`，重新收敛，直到没有新的沿（上限 64 轮）。
- 验证：异步 2 位计数器 `00→01→10→11→00`。

### G9 生成器里一个写反的三元表达式，把总线网整体漏掉
- 症状：`Q` 恒 `UUUU`，但内部计数明明在动（`CARR` 正常）。
- 根因：`("cp","bus") if mirror else ("cp","bus")` 两个分支一样，`bus` 在所有构建里都被剔除。
- 解决：两套网络集合显式列差异键，并加断言"正式构建必须包含 bus 网"。
- 验证：`Q` 全 `U` 而 `CARR` 正常 = "内部对、出口断"的指纹。

### G10 生成的文件 Logisim 不认引脚（类型写成 `in` / `out`）
- 症状：文件能打开，但引脚没有箭头、网络全 `U`，体检报一堆"孤立端口"。
- 根因：5.0 只认 `<a name="type" val="input"/>` 或 `val="output"`；写成 `in` / `out` 会被当成无类型引脚。
- 解决：用 `circ_build` 生成（它写对），手改 XML 时注意这一条。
- 验证：`circ_audit` 的 `dangling` 会立刻爆出来。

### G11 NOT 门接不通
- 症状：按 −50 / −60 接 NOT，两种都输出 `E`。
- 根因：NOT 的画框是 −30..−10，宽度按 30 算，输入口在 −30，不符合"反相圈 +10"的规律。
- 解决：优先用 `NAND(a,a)` 或直接取触发器的 `~Q`；非用不可时按 −30 接。
- 验证：6 组偏移扫描只有 −20/−30 连通（−20 是靠 `WireRepair` 吸附，别依赖）。

### G12 真值表跑到一半卡死 / 爆内存
- 症状：`-t table` 长时间无响应。
- 根因：n 个输入 = 2ⁿ 行。12 个输入 4096 行，16 个输入 65536 行。
- 解决：`circuit_truth_table` 已内置保护——输入 >16 直接拒绝，行数默认截断 4096（`max_rows` 可调）。
  验大电路用 `circ_sim` 抽样，或把无关引脚去掉再验。
- 验证：给一个 20 输入的空电路，应当直接返回拒绝信息而不是卡住。

## H. 8 位总线项目新增（原码乘法器，2 万+ 导线规模）

完整上下文：生成器在 `scripts/lib8.py`（几何+XML）、`scripts/route8.py`（确定性布线+自检）、
`scripts/sim.py`（向量测试封装）。

### H1 A* 迷宫布线在「密排端口 + 8 路扇出」下静默失败
- 症状：个别位输出 `E`，失败位随布局微调而漂移，永远修不干净。
- 根因：A* 只保证"自己走得通"，不检查与已有线共线重叠 / 端点搭上别人的拐点（T 型短接）。
  端口 10px 密排、通道一挤，这类碰撞概率急剧上升，且生成阶段零报错。
- 解决：放弃迷宫布线，改确定性布线——每个网络独占通道、固定折线模板
  （`z()` 水平-竖直-水平 / `w()` 任意折线），写出文件前逐条自检（见 H2 的检查清单）。
  自检报错就当场失败，绝不带病落盘。
- 验证：fa1 8/8、add8 37/37、neg8 512/512 一次通过；同样布局换回 A* 必现 E。

### H2 通道选在端口「反侧」会回折，短接相邻线——且不显示 E
- 症状：`clk`/`reset` 这类输入网"线画到了、电没到"，寄存器后半区根本不动。
  输出网短接会显示 E，输入网短接什么都不显示，排查极其痛苦。
- 根因：自动选通道时目标落在端口短桩的另一侧，走线回折，合并后多出一截 10px 短线，
  端点正好落在相邻竖线上 = T 型短接。自检只查了"新线端点压旧线"，没查反向。
- 解决：三条规则加进布线自检——
  ① 通道必须落在端口正确一侧（距端口 ≥30px，留出短桩）；
  ② 跨网端点重合 = 短路（双向都查：新线端点压旧线、旧线端点压新线）；
  ③ 网络连通性检查（`verify_nets`：每个网络的所有端点必须连成一片，抓"主干太短/分支悬空"）
  加电气短接检查（`verify_short`：按"端点落在导线上才算连"重建电气网络，报告不同命名网被短接）。
- 验证：reg8 时钟主干只画到一半（后 7 个 DFF 没接上）就是 verify_nets 抓出来的。

### H3 ≥4 输入门的端口几何不可靠，拆两级 2 输入门
- 症状：4 输入 AND 做译码（cnt==8）时输出低位 `E`。
- 根因：自家 `gate_geom` 的多输入间距公式只对 3 输入验证过；4 输入时端口跑到元件盒外。
- 解决：4 输入逻辑改写为两个 2 输入门级联（如 `zero = (¬c3·¬c2)·(¬c1·¬c0)`）。
  规则：每引入一种新端口数（尤其 ≥4），先单独做一个最小电路跑真值表验证几何。

### H4 大扇出供电用 Constant，别用 Ground 阵列
- 反例：8 个 Ground 加 8 路合并分线器拼一条 0 总线——9 个元件、8 段短桩线，
  每一段都是潜在短接点。
- 正确：`<comp lib="0" name="Constant">` 带 `<a name="value" val="0x00"/><a name="width" val="8"/>`，
  一个元件输出 8 位 0，直接接加法器 `b` 输入。`value` 是十六进制字符串、`width` 是位数。
- 附带：常量 1（`val="0x1"`，width 缺省 1）也是 cin=1 / 使能类的首选。

### H5 顶层自动仿真必须放 Clock 组件；运算电路保留 clk 引脚
- 根因：`Ctrl+K`（启用时钟模拟）只驱动 Clock 组件；引脚 `clk` 自己不会跳变。
- 做法：`main` 里放 Clock（输出口就在 loc 本身），电路属性写 `simulationFrequency`（如 8.0）；
  `mul` 里保留 `clk` 引脚供 `-w` 向量测试。两套驱动互不干扰，共用同一份子电路。
- 演示脚本：Poke 设操作数 → reset 点 1 再点回 0 → Ctrl+K，计数器走到终点即出结果。

### H6 展平（paste）子电路的两个坑
- 坑 1：内部残留子电路。展平 `add8` 后它内部的 8 个 `fa1` 实例不再有定义，
  Logisim 静默把实例当未知元件 → 加法器输出全 `U`。展平前必须确认源电路是纯门级。
- 坑 2：引脚 y 顺序会变。展平后 `mul` 的引脚排布与分层版不同（reset/clk 顺序对调），
  顶层若按旧的硬编码偏移接线，`reset` 会接到 `clk` 上——product 恒 0 且无任何报错。
- 解决：顶层连线永远读实例端口坐标（`b.sub()` 返回的 dict），不硬编码偏移。

### H7 向量列数不匹配 → 静默跳过 → 假通过
- 症状：少写一列 `<DC>`，Logisim 只打印「正在加载测试向量」，仍报「通过：N」——
  一行都没比对，N 还是表格行数时更迷惑。
- 解决：写完向量必做一条——
  ① 故意写错一行期望值，确认报 `失败：1` 再改回；
  ② 或断言 `通过数 == 行数`（`scripts/sim.py` 的 `verify_alive()`）；
  ③ 确认表头字段数与每行字段数一致。

### H8 mux 的选通语义是 `y = s ? b : a`
- 症状：累加器永远不累加，数值对一半。
- 根因：把 `A+M` 接到 `a`、`A` 接到 `b`，实际做成 `Q0 ? A : A+M`，正好接反。
- 教训：选择器接反不报错、不显示 E，只是逻辑错；给可疑节点加探针引脚逐拍看
  中间寄存器才能定位。加一个 8 位 output 引脚是最快的观察手段。

### H9 求补器的选择端各接「自己的」符号位
- 症状：正数用例全对、负数全错（输出正的幅值）——非常迷惑的组合。
- 根因：两个 `|op|` 求补器的 `s` 端都接了乘积符号 `s1⊕s2`，等于对负操作数求补两次
  （`neg8` 内部是 `x⊕s + s`，s=1 时取反加一，两次后回到原值）。
- 教训：同类功能块多处实例化时，逐个核对控制端来源；「正数对、负数错」是求补类 bug 的指纹。

### H10 迭代次数 = 数据拍数 + 装载拍数
- 症状：乘积正好是真值的 2 倍。
- 根因：装载占 1 拍，只做了 7 次加-移位；原码一位乘法 n 位幅值要 n 次，8 位幅值 = 8 次，
  总拍数 = 1 + 8，终止条件是 `cnt == 9`。
- 教训：先写 Python 参考模型逐拍对拍，再定硬件终止条件。

### H11 网络别名要在展平前归一（canonicalize）
- 根因：构建器里同一进位链用了 `c1`/`ca1` 两个名字（电气上相连），分层时无害；
  展平合并后布线自检会把新走线误判为短路。
- 解决：`paste()` 前先跑 `canonicalize()`——按「同名或端点相接」做并查集归并，
  每组取最短名字为代表。

### H12 Windows GUI 自动化（沙箱内）
- 坑：PowerShell 的 `Add-Type` 加载 WinForms 和 COM `WScript.Shell` 在沙箱里会被拒。
- 可用路径：`ctypes`（EnumWindows/ShowWindow/SetForegroundWindow/mouse_event/keybd_event）
  加 `PIL.ImageGrab.grab(bbox=窗口矩形)` 截图。要点：
  ① 截图坐标按 DPI 缩放换算（截图像素不等于 SetCursorPos 逻辑像素）；
  ② `Ctrl+滚轮` 缩放画布、`Shift+滚轮` 横向滚动；
  ③ 后台任务里启动的 GUI 会在任务结束时被回收——给用户看要提示重开。
- Logisim 打开方式：命令行 `java -jar xxx.jar 文件.circ`；`.circ` 默认无文件关联，双击无效。

### H13 文件关联与桌面快捷方式（免管理员）
- 关联：写 `HKCU\Software\Classes\.circ`（默认值 = ProgID，如 `LogisimCircuit`）→
  `...\LogisimCircuit\DefaultIcon`（ico 路径）→ `...\shell\open\command`
  （`javaw.exe -jar "jar路径" "%1"`）→ `.circ\OpenWithProgids` 加 ProgID；
  最后调 `SHChangeNotify(0, 0x08000000, None, None)` 刷新图标缓存。Python `winreg` 即可。
- 快捷方式：`pywin32` 不可用时用 `ctypes` 直接调 COM——`CoCreateInstance(CLSID_ShellLink)`
  后按虚表下标调 IShellLinkW（SetPath=20、SetArguments=11、SetWorkingDirectory=9、
  SetIconLocation=17）与 IPersistFile（QueryInterface=0、Save=6），注意结构体首字段是 vtable 指针。
- 图标：从 jar 里 `unzip` 抽 `resources/logisim/img/logisim-icon-256.png`，
  PIL 存 ICO（sizes 16/32/48/128/256）。

### H14 多比特门的 `width` 是整片位宽，1 位信号直连 → 输出恒 0
- 症状：用 8 位 AND 做清零掩码，主电路三个数码管永远 `000`；向量 4096 组只过 5 组。
- 根因：`<a name="width" val="8"/>` 是门的 Data Bits（实测 `0x0f AND 0x10 = 0x00`），
  门的每个输入口都是 8 位；另一个输入接 1 位网络就是位宽冲突，整条网络按 `E` 处理，结果落成 0。
- 解决：需要「全 0 / 全 1」掩码时，用分线器（合并方向）复制信号：
  `fanout=n`、`facing=west`，n 个位口用同一根竖线串起来（同网串接合法），
  合并口输出正好是 `0x00` / `0xFF`，再拿去与总线。
- 验证：改完必须补 `restart=1` 的用例，否则这条支路根本没被验过（本次 4096 + 5 = 4101 全过）。

### H15 `circ_audit` 在 `<main>` 指向真实主电路后会跨电路串名
- 症状：把 `<main name="fa1"/>` 改成 `<main name="main"/>` 后，audit 从 8 网络/20 端口 变成
  85 网络/214 端口，报 `fa1` 的 a/b「有读无驱动」、数码管 `p` 口「孤立」、AND 输出悬空。
- 根因：它按引脚标签建网表，跨电路同名标签（`a`/`b`/`p`）被并成同一张网。
- 解决：audit 只信 `conflict` / `body_overlap`；连通性以 Logisim 原生 `-w` 向量
  + 本体截图为准（数码管显示 `0` 而不是 `E`，就说明输入接到了有效电平）。

### H16 Hex Digit Display 的 `label` 在 5.0 不渲染
- 对照实验：两个数码管，一个 `label="L百位"`、一个空 → 图上都没有字。
- 解决：位名/说明改用 Text 批注（`lib="4" name="Text"`，属性 `text`、`font`）。
  注意 Text 锚点是左下（文字画在 loc 之上），按"文字中心"估位会压到元件上；
  字号 12 缩小后几乎看不清，标题用 `bold 14`。

### H17 电路贴在 x≈0 时，多位引脚的标签被左侧面板切掉
- 症状：截图里只看到 `ult_op1`，以为标签没写。
- 根因：引脚标签画在引脚框左侧，多位引脚的框比 1 位长一截，x 太小时整段落在面板下面。
- 解决：整块右移（本次 +140）后重新截图确认。这类问题 audit 和 `-w` 都看不出来，
  只能靠本体截图；用 `translate_block()` 正则平移比手改坐标安全，平移后要重跑向量。

### H18 GUI 自动化的补丁（承接 H12）
- ① `open_circ()` 从一次性脚本里起的 java 进程会随父进程退出被杀——窗口刚起来就没了。
  用 MCP 的 `circuit_open_gui` 打开（挂在服务进程下），或 background 常驻。
- ② `gui.foreground()` 要传窗口句柄；传 `wait_window()` 返回的 `(hwnd, title)` 元组会 TypeError。
- ③ `Ctrl+滚轮` 只对「缩小」稳定生效（`wheel(h, n, ctrl=True)`，dy 负 = 缩小）；
  放大用 `Ctrl+=` / `Ctrl+-`（VK 0xBB / 0xBD）。
- ④ 截图是整窗像素（如 1720×1033），人看的是缩放后的预览（如 1080 宽），
  按肉眼坐标点击会整体偏 1.59 倍。要点元件先用像素检测（找蓝色标签文字 / 深色矩形）
  把变换量出来，别凭感觉点。
- ⑤ 多比特输入引脚在 5.0 里点一下只是选中（粉框），不会翻位；
  文档里别写没实测过的手势，交给用户自己点。

### H19 手写 `<appear>` 的必备项（承接外观编辑）
- 标志位：`<a name="appearance" val="custom"/>` + `<a name="circuitnamedboxfixedsize" val="true"/>`
  两个都要有；`<appear>` 要放在属性行之后、`<comp>` 之前（照 Logisim 自己的输出顺序）。
- 两个坐标系：`<circ-port x y>` 是符号坐标（相对 `<circ-anchor>`，父电路看这个），
  `pin="x,y"` 才是内部 Pin 的绝对坐标。移动内部 Pin 只改 `pin`，端口 `x y` 不动。
- 父电路：端口绝对坐标 = 实例 `loc` + 外观端口坐标（用 2.3.circ 的 add8 复核过：
  `loc(740,160)+(0,30)=(740,190)` 正好落在一根导线上）。
- 最省事的做法：外观 spec 和父电路布线用同一份数据算，一次生成，
  不存在"先改外观、再回头补父电路导线"的返工。

### H20 空 `<toolbar/>` 会让顶部工具条消失
- 症状：打开 `.circ` 只有画布，没有 Poke/Edit/Wiring/Text 按钮，用户以为软件坏了。
- 根因：`<toolbar/>` 是空工具条；Logisim 不会自动回退到默认工具。
- 解决：写全四项 + 分隔符：
  `<toolbar><tool name="Poke Tool"/><tool name="Edit Tool"/><tool name="Wiring Tool"/><tool name="Text Tool"/><sep/></toolbar>`。

### H21 10px 断口：端口都“碰到了线”，整网却悬空
- 症状：子电路向量全 `U`；`circ_audit` 不报错，人工看每根线都像接上了。
- 实例：`r1l` 总线画到 `(630,240)`，主干却从 `(630,250)` 开始——读地址整条悬空，
  8:1 选择端 `U`，`rdata1` 全 `U`。
- 根因：只校验了“每个端口被某段线碰到”，没校验这些线段彼此连通。
- 解决：生成器加整网连通性检查：线段按“共享端点 / 端点搭线”做并查集，
  必须只有一个连通块；不通过就不写文件。`circ_audit` 的 floating/dangling 不能代替它。

### H22 译码器 sel/en 在底部，只能从下往上接
- 5.0 实测：`sel=(0,0)`、`en=(-10,0)`；包围盒 `(-20,-10*(2^n+1),40,10*(2^n+1)+10)`；
  输出在右侧 `x=+20`，从 `y-10*2^n` 到 `y-10`（最上面是 out0）。
- 从左侧或上方接线会压进符号；en 与 sel 只差 10px，横线接 sel 会先撞 en。
- 正确做法：sel / en 各自从下方拉两根平行的 10px 竖线进来。

### H23 分线器朝向与位序（east / west 都是 b0 在上）
- east：bus `(0,0)`，分线 `(20,-10*(n-k))`，b0 在最上；体 `(0,-10n,21,10n+1)`。
- west：bus `(0,0)`，分线 `(-20,10*(k+1))`，b0 仍在最上；体 `(-20,0,21,10n+1)`。
- 把 5 位拆成 3+2 再合并：east 拆分 → west 合并，天然“左进右出”，
  两个 splitter 的 1 位端口等高直连，不用绕线。

### H24 外观端口 `pin=` 是内部坐标，`x y` 才是父电路坐标
- 重新生成电路时最容易翻车：内部 Pin 挪了，`appear` 里的 `pin="x,y"` 必须同步；
  `x y` 千万别动，否则父电路导线整体脱开（全 `U`）。
- `probe_component` 返回的是符号端口坐标与位宽；它按内部 Pin 的 y 排序推名字，
  改了 Pin 布局后名字会错位——只拿坐标/位宽当依据，别信 name。

### H25 诊断探针差 10px 会给出假 `U`
- 实例：探 `clk` 时把 Pin 接在 `(650,330)`，真正的 clk 分线是 `(670,330)→(700,330)`，
  读出 `U`，误判“时钟没到”，白查两小时。
- 规则：探针落点必须先确认在某条线段的内部或端点上；否则读到的是空白点。
  先用几何表算出线段范围，再放 Pin。

### H26 向量里“释放复位 + 时钟上升沿”不能放同一行
- 症状：写操作看似执行，下一行读回还是 0。
- 根因：同一行同时把 reset 1→0、clk 0→1，寄存器可能仍按“复位中”处理。
- 解决：复位释放单独一行（clk 保持 0），下一行再给上升沿；配合 `<set>/<seq>` 分组。

### H27 有标签的引脚 20px 密排会互相压住
- 症状：父电路 `waddr/wdata/wen/clk` 标签叠成一团，截图看不清。
- 解决：引脚拉到 40px，用正交折线扇入模块 20px 的端口；
  竖线按“越靠上的引脚走越右”排序，H 段与回接段都零交叉。

### H28 子电路内部旁路会让父电路旁路变冗余
- 现象：`EightRegs` 内部已有 `(raddr==waddr && wen) → wdata` 的旁路；
  `FourEights` 顶层再比一次 5 位地址，逻辑等价，却多两个比较器、两个与门、两个 2:1。
- 规则：先确认子模块是否已处理同址旁路，避免重复实现；
  若保留，两边比较位宽必须一致（3 位 vs 5 位不能混）。

## I. 存储器 / 工程头 / connect 盲区（3.2 存储器实验新增）

### I1 工程头缺 `#Plexers`，Mux/Decoder 全变未识别元件
- 症状：整机 `DOUT` 全 `U`；GUI 打开提示「找不到库“5”」。
- 根因：`lib8.project()` 只声明 `#Wiring/#Gates/#Memory/#I/O/#Base`（0~4），
  用了 `Multiplexer/Decoder`（lib=5）却没写 `<lib desc="#Plexers" name="5"/>`。
- 解决：生成后检查工程头；缺库不会在 `-w` 时报错，只会把 mux 输出当 `U`。

### I2 建了 Pin 不等于入网：A/DIN 漏接会让地址/数据全 `U`
- 症状：地址/数据全 `U`；RAM 写不进、读回全 `FF`。
- 根因：`add_pin()` 只创建引脚元件，还必须显式把 pin 坐标加入某条 net。
- 解决：生成后断言「每个声明的 Pin 至少出现在一条 net 的端点里」；不满足不落盘。

### I3 `lib8.Board.connect()` 不写 `_net_terms`，`verify_nets` 对它是空验证
- 症状：断线/漏接的网也能「自检通过」，功能测试才暴露。
- 根因：`route8.verify_nets()` 只检查 `z/w` 路由注册的 `_net_terms`；
  `connect()` 只写 `self.nets` 和 `term`。`verify_short` 只查短路，查不出开路。
- 解决：自己记录每根 connect 网的预期端点，用并查集检查所有端点在同一连通块。

### I4 4 bank 低位交叉先定字节序：bank0 是 LSB
- 症状：字节读「错位」，误判成 mux 选择反。
- 根因：`bank i` 存地址 `4k+i` 的字节时，字 `0x11223344` 的
  `byte0=0x44、byte1=0x33、byte2=0x22、byte3=0x11`；按大端写期望值就会错。
- 解决：测试向量里先写清 bank 映射与字节序，再写期望值。

### I5 `.circ.autosave` 会让 `-t stats` 报「加载电路文件出错」
- 症状：`-w` 可能还能跑，但 `-t stats` 直接报加载失败。
- 根因：GUI 会话异常退出/未保存留下 `.<文件名>.autosave`。
- 解决：无头运行前关闭 GUI，删除同目录的 `.circ.autosave`，再重跑。

### I6 `circ_audit` 对 RAM/ROM/Bit Extender 只给 partial
- 症状：正常连接被列成 `dangling`，结论标 `partial`。
- 根因：网表重建不支持 Memory 库的 RAM/ROM 和 Wiring 的 Bit Extender。
- 解决：存储器/总线电路以生成器几何自检 + Logisim `-w` 功能向量为准；
  `audit` 的 `dangling` 不能全信。

### I7 手写调试 `.circ` 可能让 Logisim 卡死或弹窗
- 症状：`-w` 长时间无响应，headless 下只能 kill Java 进程。
- 根因：手拼 XML 容易出现非法线、端口压线或宽度冲突。
- 解决：调试电路也由生成器产出；调试文件放 `%TEMP%` 或 `_debug/`。

### I8 `circ_appearance preview` 截的是外观视图，不是 circuit view
- 症状：`main` 截图只有一个空框，看不到电路布局。
- 根因：`preview` 会切到 Edit Circuit Appearance；没有自定义外观的 `main` 只显示端口框。
- 解决：主电路布局用 GUI + 窗口截图（System.Drawing/PrintWindow）；
  子电路符号才用 `preview`。`shot.py/wincap.py` 依赖 PIL，环境没有 PIL 时会失败。

### I9 RAM/ROM 5.0 实测端口
- 16K×8 RAM：`addrWidth=14,dataWidth=8,enables=byte,type=volatile,trigger=rising,`
  `asyncread=true,databus=bibus,clearpin=false`；体 `240×250`；
  `A(0,10) / D(0,90) / Q(240,90) / WE(0,50) / EN(0,60) / CLK(0,70)`；`EN` 是 OE，接 1。
- 16K×32 ROM：`A(0,10) / Q(240,60)`，体 `240×220`。
- 其他位宽用 `circ_probe` 实测，不要照搬。

### I10 Splitter 分支等宽：16→14+2 要 8×2 拆分再 7×2 合并
- 根因：Logisim 的 fanout 分支宽度固定为 `incoming/fanout`，不能直接拆成 2 位+14 位。
- 解决：16 位用 `fanout=8` 拆成 8 个 2 位分支，`b0` 作字节通道，
  `b1..b7` 用 `fanout=7/incoming=14` 的 west 合并成 14 位字地址；`b0` 永远在最上。

### I11 ROM contents 格式：`addr/data: 14 32` + 十六进制值列表
- 属性值写成 `addr/data: <addrBits> <dataBits>` 后跟十六进制值列表；
  只写前 64 个字时其余地址按 0 填充。
- 32 位 ROM 每值 8 位十六进制，8 位 ROM 每值 2 位，不要写 `0x` 前缀。

### I12 `-w` 的 `<set>/<seq>` 可跨子电路保留状态
- 同一 `<set>` 内按 `<seq>` 递增执行，状态会保留到下一行，子电路实例内部状态也保留。
- CLK 用 0→1 两行制造上升沿，写行期望值用 `<DC>`。
- 列名对不上时 Logisim 静默跳过，必须确认「通过数 == 数据行数」。

## J. Logisim 2.7.1（32 位 CPU / DM 纠错）

> 2.7.1 与 5.0 的库索引、端口、元件语义都不同：不要用 `circ_audit/circ_sim/circ_geometry`，
> 用 `circ271_check/circ271_sim/circ271_ports`。完整复盘见 `cpu271-casebook.md`。

### J1 Splitter 分支端口 y 坐标算错，分支静默悬空
- 症状：`bank` 只有 2 位却读成 `x`，读 MUX 选择 x，`lw` 读回 x；检查器报「位宽冲突」或什么都不报。
- 根因：2.7.1 east 分支在 `y - 10*fanout + 10*i`（不是 `y + 10*(2i-fanout)`）；west 在 `y + 10*(i+1)`。
- 定位：`circ271_ports` 看 Splitter 的 `b0/b1` 实际坐标。
- 解决：按实测坐标接线；保存后 `fanout` 会被省略，工具需从 `bit0..bitN` 推导。

### J2 门电路默认 5 输入，接 2 根线会输出 x
- 症状：`wr=x`，Decoder 输出全 x，RAM 行为异常。
- 根因：2.7.1 AND/OR 门 `inputs` 默认 5，输入口在 `x-50`、纵向 40px 内均布（2 输入为 `y±20`）；
  只接 2 根线时另外 3 个输入悬空。
- 解决：显式 `inputs=2`，并核对引脚坐标（不是 `y±10`）。

### J3 Decoder 禁用输出默认悬空，RAM 每个时钟沿都写
- 症状：`MemWrite=0` 时内存仍被改写；`lw` 结果被同一拍的写操作污染。
- 根因：2.7.1 Decoder 禁用输出默认 `Z`；RAM 的 WE 判定是「引脚 ≠ FALSE 即写」，悬空被当成写使能。
- 解决：Decoder 加 `disabled=0`；或每路 `str` 用 AND 门与 `wr` 明确拉 0。

### J4 Decoder / MUX 的 `sel`、`en` 必须从符号下方接入
- 症状：横穿符号体后该脚显示悬空/红色，选择和使能失效。
- 解决：`sel/en` 从下方引线；`Comparator` 的输出同理不能向体内走。

### J5 RAM 底部五个控制脚，CS/OE 悬空是合法的
- 2.7.1 RAM：`str(-110) / cs(-90) / clk(-70) / oe(-50) / clr(-30)`，`Q(0,0) / A(-140,0) / D(-140,20)`。
- `cs/oe` 悬空按「选中/使能」处理（`!= FALSE` 判定），不会导致读 x；不要误判成漏线。
- 真正要小心的是 `str`：悬空 = 一直写。

### J6 Register 的 `en` 悬空等价使能
- 症状：原文件 `en` 没接，PC 却正常 +4，看起来像 bug 又不是。
- 根因：2.7.1 Register 只在 `en == FALSE` 时禁止加载，悬空(unknown) ≠ FALSE。
- 建议：显式接 1 位常量 1，消除隐式语义；把常量强制改成 0 可验证它确实控制加载。

### J7 `Pin.setValue` 只存值，不会触发传播
- 症状：Java 引擎测试里设置输入后电路毫无反应，寄存器/内存都不动。
- 根因：`Pin.setValue` 只写入 `PinState.sending`，没有把组件标脏。
- 解决：`state.markComponentAsDirty(pin)` 后再 `propagator.propagate()`。

### J8 子电路实例端口 ≠ 内部 Pin 坐标平移
- 症状：按「Pin 坐标 + 固定偏移」去父电路找端口，全部对不上。
- 根因：2.7.1 子电路实例端口按侧/顺序打包（实测 10px 间距），与内部 Pin 的 40/70/90px 间距无关。
- 结论：子电路内部可自由重排布局，只要接口 Pin 的集合/侧不变，父电路不用改。
- 定位：`circ271_ports` 只能看内部；实例端口必须用 Logisim 引擎（`Component.getEnds()`）实测。

### J9 2.7.1 没有原生测试向量
- `-w` 是 5.0+ 的能力；2.7.1 的 `-t` 只有 stats/table 等有限功能。
- 解决：用 `circ271_sim`（原始元件电路）或 Logisim 2.7.1 引擎的 Java 侧仿真（整机/子电路）。

### J10 Tunnel 盒子向右延伸约 45px，摆太近会压住元件
- 症状：Tunnel 盒子盖住 RAM 左边缘 / Splitter / 门，截图上看像短路，实际网络没错。
- 解决：Tunnel 连接点与下一个元件留 ≥40px；多 Tunnel 纵向间距 ≥20px。
- 检查：`OverlapCheck`（`Component.getBounds()` 两两求交）。

### J11 保存后属性被省略，检查器误报
- 症状：用户保存过的 2.7.1 文件，检查器报「位宽冲突 [2,10]」「memwrite=0 仍写」。
- 根因：Logisim 会省略等于默认值的属性：Splitter 的 `fanout`、Decoder 的 `enable`。
- 解决：工具按推导值/默认值处理（`fanout = max(bit 映射)+1`，`enable` 默认 true）。

### J12 单块 4096×32 RAM 当 3072×32 用：越界写会回绕
- 症状：写 `0x3000` 后 `0x0000` 被改成 `0xFFFFFFFF`；写 `0x0004` 读 `0x0007` 得 0。
- 根因：12 位地址截断（`0x3000 & 0xFFF = 0`），且字节地址直接当字地址。
- 解决：3×1024×32 + `ALU[13:2]`（10 位 offset + 2 位 bank）+ `ALU<0x3000` 与 `MemWrite` 相与门控。
- 验证：`circ271_sim` 的「同字 0x0007」「越界 0x3000」两项必须 PASS。

### J13 分支测试用例要能区分「跳过/未跳过」
- 症状：`add $6,$0,$0` 无论分支是否成立结果都是 0，测试看起来永远通过。
- 解决：看 PC 序列（`0x3018 → 0x3020` 才是跳过），或让被跳过的指令写入一个非零特征值。

### J14 写使能线漏一段：某个寄存器每拍被写，评测 trace 整体错位
- 症状：单条 `lw $27, 0($5)` 看似正确（$27 那一拍确实拿到 ReadData），但评测器报
  「got `@0x307C: $27 <= 0xffffffff` when expected `@0x3060: $17 <= 0`」，
  且报错位置“紧挨着”一条正确指令。
- 根因：GRF 中 $27 的写使能 AND 门到 `en` 的**横线缺失**（只有竖线 `(870,610)->(870,650)`，
  漏了 `(870,610)->(910,610)`）。`en` 悬空在 2.7.1 中 ≠ FALSE → **等价使能**，
  $27 每个时钟沿都被写入当前 WD；评测器逐写事件比对 trace，多出的事件导致序列错位，
  `0xffffffff` 只是错位后对齐到的某一拍 WD。
- 定位：写一个「给 r1..r31 各写唯一值再读回」的扫描程序，只有 r27 不生效；
  再对照相邻寄存器（如 $26）的 en 走线，一眼看出少一段。
- 解决：补 `(870,610)->(910,610)`。修复后还要验证时序：`ori $27,$0,0x1B` 之后继续执行
  其它 `ori`，r27 必须保持 0x1B（不再每拍被覆盖）。
- 预防：有写使能的阵列（GRF、RAM bank）必须**逐单元扫描**，不能只测前几个寄存器；
  悬空 `en/cs/oe` 一律当成可疑项。

## J 组：Logisim-ITA 2.16 / 经典 2.7.1 专属（与 evolution 5.0 的几何差异）

### J1 子电路外观矩形比端口小 → **所有端口被静默丢弃**
- **症状**：`REG32` 子电路实例的 `Component.getEnds()` 返回**空列表**，
  父电路连到该实例的线全部悬空；仿真读输出恒 `U`，但**不报任何错**。
- **根因**：2.7.1 的 `CircuitAppearance.getPortOffsets()` 丢弃落在外观矩形
  边界/内部的端口。`rect` 100×70、端口在 `x=0`（左边界）时 4 个端口全消失。
- **解决**：外观矩形**四周内缩 10px**（`rect x=10 y=10 w=W-20 h=H-20`），
  让端口落在矩形**外侧**。老师的模板就是这么画的（端口 `x=56`，rect 从 60 起）。
- **验证**：`scripts/ita_probe.py ends` 看实例有没有 `END` 行。

### J2 外观端口连接点不是 `x,y`，有固定偏移
- **实测**：`实际 = loc + (x + (portW-1)//2 - 2, y + portH//2 - 3)`
  - `width=32 height=8` → `(+13,+1)`；`width=1 height=8` → `(-2,+1)`；
    `width=5 height=10` → `(0,+2)`
- **解决**：统一 `width=8 height=8`，XML 写 `desired-1`，实际点正好 `loc+desired`，
  父电路布线直接用 `desired`。
- **教训**：**别把 5.0 的 `loc+(x,y)` 套到 2.7.1 上**。

### J3 2.7.1 门输入口在 `(x-30, y±step*(n-1)/2)`，不是 `(x-50, y-20+i*step)`
- **症状**：AND/OR 输入线接在门体外 20px，输入悬空 → 输出恒 `E`，
  并沿写使能链把整列寄存器的 `WE` 全染成 `E`，而 `--errors` 只报输出端。
- **实测**：2 输入 `in0=(x-30,y-10)`、`in1=(x-30,y+10)`、`out=(x,y)`；5 输入 step=10。
- **已修**：`scripts/circ271.py` 的 `GATE_NAMES` 分支。

### J4 分线器位口位置与组编号
- **端口**：`bus=(x,y)`，`b_i=(x+20, y+10*(i-fanout+1))`；fanout=2 时
  `b0=(x+20,y-10)`、`b1=(x+20,y)`。
- **b0 是低位组**（`bit0..` 那组），生成 `bits=[0,0,0,1,1]` 时 b0=3 位、b1=2 位。
- **坑**：按演进版公式 `y+10*(i-fanout)` 算会整体高 10px，5 位总线压在 2 位位口上。

### J5 主干穿过"元件端口"会形成 T 接 → 把不同位宽短接
- **症状**：`位宽不匹配 (N)`，但看不出是哪几根线。
- **本例四处**：CLK 主干 `y=520` 穿过模板 32 位隧道 `(820,520)`；
  WE 竖线 `x=320` 穿过分线器位口 `(320,550)/(320,560)`；
  WE 横线 `(320,110)→(270,110)` 穿过 CLK 隧道 `(280,110)`；
  WA 主干右端 `(360,790)` 落在 D 竖线 `x=360` 上。
- **规则**：导线**中段交叉不连**，但**端点/端口落在线段上一定连**。
  排线要么让端点避开所有端口坐标，要么换一条不经过端口 x/y 的通道。
- **定位**：`python scripts/netcheck.py file.circ "电路名"`，按真实端口坐标建网。

### J6 2.7.1 没有 `-w` 向量引擎，必须自带 headless 探针
- **事实**：`-tty` 只有 `stats/table/tz/time`，`table` 仅组合电路；
  寄存器堆这类时序电路无法用官方命令行验证。
- **方案**：`scripts/ita/ITAProbe.java` + `scripts/ita_probe.py`，
  直接调类库：`Loader.openLogisimFile` → `Project` →
  `proj.setCurrentCircuit` → `proj.getCircuitState()` → `Pin.setValue` + `propagate`。
- **三个必须做对**（否则全 `U`）：
  1. 先 `proj.setCurrentCircuit(circuit)` 再 `getCircuitState()`；
     自己 `new CircuitState` 是游离状态，驱动不了也读不到网络。
  2. `Pin.setValue` 只改 PinState，**必须再 `Pin.propagate(is)`** 才写到端口。
  3. `CircuitState.getValue(loc)` 对导线中点返回 null，只能读端点。
- **局限**：多子电路实例（32 个 REG32）的时序向量偶发误报
  （同结构两个 MUX 一个正常一个 `U`），**最终以 GUI 本体为准**。

## K. Logisim-ITA 2.15.0.2（构建加法器实验新增）

### K1 别用 .circ 的 source 属性判断 Logisim 版本
- **坑/规则**：`<project source="2.16.1.0.exe">` 只是保存时那个 exe 的文件名；同一台机器上可能同时存在 2.15.0.2 的 exe 与 2.16.1.0 的 jar。要拿真实版本，用 `javap -c -p -cp <jar> com.cburch.logisim.Main` 看 static 初始化里的 `LogisimVersion.get(major,minor,release,rev)`。
- **证据**：实验2：上传的 logisim.exe 标题栏 2.15.0.2，而待修目录的 .circ 全是 2.16.1.0.exe 保存的

### K2 整块替换给定框架电路会丢 Pin/Tunnel/外观
- **坑/规则**：把老师给的验证电路整段替换成新生成的 <circuit>，会丢掉原有 Pin、Tunnel、Probe、Splitter 与 <appear>；加载时报 `Appearance element circ-port not found`，文件打不开。正确做法是保留原电路内容，只把新元件/导线追加到 `</circuit>` 之前。
- **证据**：实验2 加法器：四个框架被替换后 7 个电路全部无法加载

### K3 2.15.0.2 门端口：AND/OR x-30、XOR x-40、NOT x-20
- **坑/规则**：实测 Logisim-ITA 2.15.0.2：AND/OR 输入口 `(x-30, y±…)`，XOR 输入口 `x-40`，NOT 输入口 `x-20`（不是 -30）。NOT 写成 -30 时输入悬空，输出直接 E。
- **证据**：实验2：NOT 接错后 Overflow 恒为 E，其余输出正常

### K4 偶数输入门的中间空档是 20px
- **坑/规则**：2 输入：y-10 / y+10；4 输入：y-20 / y-10 / y+10 / y+20（中间跳过 y）；5 输入：y-20 … y+20 每 10px 一个。按“10px 均布”算偶数输入会整体错位。
- **证据**：实验2 并行进位器：4 输入与门端口错 10px

### K5 子电路外观锚点映射：loc + (端口中心 − 锚点中心)
- **坑/规则**：`circ-port` 的 x/y 是端口框左上角，映射时要用中心：端口中心 = (x + width//2, y + height//2)，锚点中心 = (circ-anchor.x + 3, circ-anchor.y + 3)。实例端口 = 实例 loc + 两者中心之差。用左上角直接相减会差 1~2px，表现为“看着接上了其实差了 1px”。
- **证据**：实验2：按该公式一次算准 5 个子电路实例的全部端口

### K6 2.x 子电路实例的 <comp> 不写 lib
- **坑/规则**：`<comp loc="(400,300)" name="并行进位器"/>` 即可；写成 `lib="8"` 会去查不存在的库，加载报「库“8”中缺少组件」。库编号 0-6 是内置库，用户电路按出现顺序隐式编号。
- **证据**：实验2 标定外观时第一次写成 lib="8" 直接加载失败

### K7 circ271_check 对 2.15 报“导线穿元件体”是误报
- **坑/规则**：circ271 按原始 2.7.1 建模（门输入 x-50、门体更宽），而 ITA 2.15/2.16 的输入口在 x-30；20px 输入短线会被判成穿体。2.15 的真实判定以 Logisim 自身 `ERRCOUNT` 与 ita_probe 向量为准。
- **证据**：实验2：并行进位器被报 45 条穿体，实际 ERRCOUNT 0、512/512 通过

### K8 netcheck.py 的 Probe 位宽 0 假冲突
- **坑/规则**：Probe 没有数据位宽，ita_probe 报告 width=0；netcheck 会把它和 4/8/16 位隧道判成冲突。每个带 6 个探针的验证框架都会稳定报 6 条假冲突，忽略即可。
- **证据**：实验2：三个框架电路各 6 条 [0,4]/[0,8]/[0,16] 假冲突

### K9 向量行字段数必须等于表头列数
- **坑/规则**：少写一列时 ita_probe 报 `bad-column-count`，整表 fail；如果列名对不上则直接报 header pin not found。4 位全加器 13 列（9 入 + 4 出），只给 3 个十进制数会 512 行全灭。
- **证据**：实验2：第一次 4 位全加器 512 行全部失败

### K10 G*/P* 期望值要从 MSB 往 LSB 递推
- **坑/规则**：组进位生成 `G* = G4 + P4·G3 + P4·P3·G2 + P4·P3·P2·G1`，`P* = P4·P3·P2·P1`。从 LSB 累加会算成 `G0 + P0·G1 …`，4 并行加法器与 16 位的 G*/P* 会大面积失败。
- **证据**：实验2：改正后 4 并行 512/512、16 位 508/508

### K11 Launch4j 的 exe 要取内嵌 jar 才能喂探针
- **坑/规则**：ITA 2.15 分发的是 Launch4j 单文件 exe。内嵌 jar 就是 `PK\x03\x04` 偏移到文件尾的整段字节；切出来可直接作为 classpath。另：加载失败时 GUI 对话框会吞异常，用 `scripts/v215/LoadTest.java` 覆写 `Loader.showError` 打印真实报错。
- **证据**：实验2：从 logisim.exe 切出 4,264,607 字节 jar，探针正常工作

### K12 Tunnel 的 facing 必须写全称
- **坑/规则**：Tunnel 的 `facing` 只认 `east/west/north/south`。生成器把 side 短码 `e/w/n/s` 直接写进 XML 时，加载报 `attribute value (e) is not valid for facing [Tunnel(...)]`，该隧道不参与连网；更隐蔽的是后续 `WireRepair` 可能死循环，探针 300s 超时。所有短码必须先映射成完整单词。
- **证据**：实验3 ALU：fan_stub 写入 `e/w` 后 B 总线全 U，SUB 用例 300s 超时；修正后 16604 行全过

### K13 分线器位口悬空会反推总线
- **坑/规则**：分线器不是纯扇出。位口悬空时它会从位侧向总线反推 0/U，和输入 Pin 抢驱动，表现为“Pin 明明有值，总线却是 0/U”。只拆低 3 位时，其余位必须接假负载（如 5 输入 OR，输出不接），或者不要用分线器、直接给总线打隧道分支。
- **证据**：实验3 ALU：A/B 总线各挂 8 位分线器但大部分位口悬空，模块输入全错；删 B 分线器 + 给 A 的 a3~a7 加假负载后恢复

### K14 无头加载会吞真实错误
- **坑/规则**：`Loader.showError` 在 headless 下弹 `JOptionPane` → `HeadlessException`，真实的非法属性/库缺失被吞掉。探针里用 `ProbeLoader extends Loader` 覆写 `showError`，把原因打成 `LOADERR ...`。“能打开但结果怪/超时”先看 LOADERR，不要先怀疑布线。
- **证据**：实验3：Tunnel facing 写 `e` 的真实报错被 HeadlessException 盖住，只看到 300s 超时；ProbeLoader 上线后一次定位

### K15 --probe / --dump 在 Pin/Tunnel 上可能读到旧值
- **坑/规则**：`CircuitState.getValue(loc)` 在输入 Pin、Tunnel 端口上不一定是网络真值；据此判断断线会误判。判断功能用 `--vector` 比输出引脚，或对子电路单独 `--set` 验证；中间网用临时输出 Pin 或子电路引脚观测。
- **证据**：实验3：A/B 输入 Pin 处 dump 恒 0，但子电路单独 eval 正确

### K16 内置 Shifter 有可变距离口，但不输出移出位
- **坑/规则**：2.15 的 Shifter 属性 `shift=ll/lr/ar/rl/rr`，8 位数据对应 3 位距离口，端口为 `data(x-40,y-10)`、`distance(x-40,y+10)`、`out(x,y)`。移位器模块可用 3 个 Shifter + 4:1；但 Shifter 不出移出位，SOL 要另算：左移 `X[8-N]`、右移 `X[N-1]`，N=0 为 0，用两个 8:1 + 2:1(S1) + AND(S1|S0)。
- **证据**：实验3：移位器 1984/1984，N=0/1/2/7 与 ll/lr/ar 全核对

### K17 MUX 忘记 enable=false
- **坑/规则**：2.15 Multiplexer 默认带使能脚；不显式 `enable=false` 时，悬空的 en 会让输出 `U/E`。关掉后：2:1 数据 `(x-30,y±10)`、4:1 `(x-40,y-20+10i)`、8:1 `(x-40,y-40+10i)`；sel 分别在 `(x-20,y+20)` / `(x-20,y+40)`；out `(x,y)`。
- **证据**：实验3：所有 MUX 统一 enable=false，移位/逻辑/比较/结果选择全部一次通过

### K18 比较结果不是“只出标志”
- **坑/规则**：实验3 比较器图是 A/B → Comparator → >/=/< → 4:1(S1S0) → 1→8 扩展器。所以 ALU 比较模式的 S 是 0x01/0x00；CF=A<B、ZF=A=B，SF/OF 无效。把 S 固定 0 会漏掉实验要求的“输出比较结果”。
- **证据**：实验3：比较器 1452/1452，A>B/A=B/A<B 的 Y、CF、ZF 全对

### K19 INC/NEC 要先把 B 置 0
- **坑/规则**：算术 1010/1011 不是 `A+B`。令 `zero_b = S3 & ~S2 & S1`，把 B_eff 置 0，再走 `B'=B_eff⊕Sub`、`Cin'=Cin⊕Sub`；INC(Cin=1,Sub=0)=A+1，NEC(Cin=1,Sub=1)=A+0xFF+0=A-1。OF 用 `(A7==Bx7)&(A7!=S7)`，CF=Cout。
- **证据**：实验3：ALU 算术 3704/3704，含 0x7F→0x80、0x80→0x7F 的 OF=1 边界

### K30 4 位立即数和跳转偏移必须符号扩展
- **坑/规则**：实验5 的 `MOV R0,-8`、`MOV R0,-4`、`MOV R1,-3` 都是负数，`JMP -5` 也是负数。2.15 的 Bit Extender 默认 `type="zero"`，会把 -8 变成 +8、-5 变成 +11。XML 要写 `<a name="type" val="sign"/>`；`Board.ext(loc, 4, 8, sign=True)` 已支持。跳转偏移同样取 `IR[3:0]` 符号扩展，不能取 `IR[7:0]`。
- **证据**：实验5：零扩展版例1 的 R2=0x50 而不是 0xB0；改 sign 后 600 行全过

### K31 S-Regs 位序：C-Reg=IR[7:6]、SA=IR[5:4]、SB=IR[3:2]
- **坑/规则**：实验4 的系统连接把 S-Regs 接成 `bit2-3=C-Reg、bit4-5=SA、bit6-7=SB`，方向正好反了；实验5 必须改为 `IR[7:6]=C-Reg、IR[5:4]=SA、IR[3:2]=SB`，`IR[3:0]` 兼作立即数（与 SB 重叠）。用已知机器码自查：`2008` 的 C-Reg=00、`0040` 的 C-Reg=01/SA=00/SB=00、`4038` 的 SA=11/SB=10。接反的症状是 MOV 写到错误寄存器、STORE 的地址/数据互换、CMP 比较错对象。
- **证据**：实验5：改正后例1/2/3/4 全过；实验4 原系统只做过模块级验证，未跑完整程序

### K32 实验5 的移位是"移 1 位"，不是 A[2:0] 位
- **坑/规则**：实验3 ALU 的 Shifter 用 `N=A[2:0]`、数据 `X=B`；实验5 的 SLL/SHR/SAR 例题都是"左移 1 位"，机器码里没有独立移位数（`0244` 的 SA/SB 只是源寄存器字段）。若直接沿用，`SLL R0`（R0=-8=0xF8，A=R0→N=0）根本不移位。系统里加 8 位 2:1 MUX：`S3S2=00`（MOV/移位）时给 ALU 的 A 送 `0x01`，否则送 RA。不要改实验3 的 ALU 本体。
- **证据**：实验5：例1 的 R0 由 F8→F0、R1 由 F8→C0，ADD 后 R2=B0

### K33 Comparator 的有符号模式是 twosComplement，不是 signed
- **坑/规则**：2.15 的 `Comparator` 属性 `mode` 只有两个合法值：`unsigned` 和 `twosComplement`（`javap -c` 可见 `SIGNED_OPTION` 的 key 是 `twosComplement`）。写 `mode="signed"` 不会报错，但比较器输出全 `U`，探针只看到 S/ZF/CF=U。实验5 例4 要 2 > -3，必须用补码比较；只需在实验5 文件里把"比较器"子电路的 Comparator 改成 `twosComplement`，实验3 文件保持 unsigned。
- **证据**：实验5：unsigned 时 2 > 0xFD 判成 A<B（CF=1）；twosComplement 后 GT=1，例4 三分支全过

### K34 复位后 T0 已为 1，IR 用 T0 取指会漏掉第 0 条指令
- **坑/规则**：CLK 模块的 2 位计数器被 RST 清 0 时，门级译码的 T0 立即为 1。释放 RST 后若 CLK 保持 0，T0 仍是 1；第一个 T0 上升沿要等计数器走完 3→0 才出现，此时 PC 已在 T3 加 1，IR 取到的是 ROM[1]。实验4 的系统实测第一拍 IR=0x8030（ROM[1]），不是 ROM[0]=0x4001。把 IR 的时钟从 T0 改接 **T1**：释放复位后的第一个 CLK 上升沿（计数器 0→1）就取 ROM[0]，PC 仍为 0。
- **证据**：实验4 系统：IRQ 首值 0x8030；实验5 改 T1 后首条 `2008` 正确执行，R0=0xF8

### K35 跳转指令必须关闭 Flag 使能，否则连续 JZ/JC 失效
- **坑/规则**：Flag 的 D 接 ALU 标志；若 en 恒为 1，JZ/JC 指令自己的 S-op（`0xA004`/`0xC003` 的高字节为 0，即 MOV B）会在 T3 把 CMP 刚锁存的 CF/ZF 冲掉。例4 的 LT 路径：CMP 置 CF=1 → JZ 不跳但把 CF 清 0 → 后面的 JC 不跳，R2 错误地保持 1。正确接法：`Flag en = ~(JP|JZ|JC)`。PC 与 Flag 同在 T3 上升沿，PC 取的是沿前的 Flag Q，所以 CMP 结果对两条跳转都有效。
- **证据**：实验5：不加门控时例4 -3<2 得 R2=1；加 `~(JP|JZ|JC)` 后 R2=0，三分支全过

### K36 INC/NEC 的 SA 字段必须指向源寄存器；15FC 才是 INC R3
- **坑/规则**：INC（S-op=10101）不是只看 C-Reg：ALU 的 A 通道由 SA 选。`0x15FC` 的 S-Regs=0xFC → C-Reg=11、SA=11，A=R3，写回 R3；`0x15C0` 的 SA=00，会把 R0+1 写进 R3，而不是 R3 自增。PDF 写的 `15fc` 是对的，不要"化简"成 `15c0`。NEC（10111）同理。
- **证据**：实验5 例3：15FC 使 R3 逐轮 0→1→2→3→4；15C0 则 R3 被写成 R0+1、不再自增

### K37 4 片 ROM + 4:1 MUX：Prog 选通与 contents 写法
- **坑/规则**：ROM 用 `addrWidth=4, dataWidth=16`，contents 为 `addr/data: 4 16\n<16 个十六进制字>`；未用字填 `0000`（MOV R0,R0，无副作用）。4 片 D 输出用隧道 `P0D~P3D` 进 16 位 4:1 MUX，`select` 接 `Prog[2]`。ROM 端口：`A(-140,0)`、`D(0,0)`、`cs(-90,+40)`，`cs=0` 使能。`PA4=PC[3:0]` 用 8→2 分线器拆，`groups=[0,0,0,0,1,1,1,1]`，分支 0（最右）是低 4 位。
- **证据**：实验5：Prog=0/1/2/3 分别跑出例1/2/3/4，600 行全过

### K38 模型化逐拍验证：负数用 8 位补码、向量值必须写 0x、临时文件名用 ASCII
- **坑/规则**：Python 侧按 ISA 建模时，`imm8` 要转成 0..255 的补码表示（`imm4 if imm4<8 else imm4+240`），PC 偏移另存有符号值（`imm4-16`）；否则 `%x` 会输出 `0xfffffff8`，8 位引脚读到 `0xf8`，所有负数用例都"失败"。`.vec` 解析器把不带 `0x/0b` 的 token 当十进制，`8030` 是 8030（0x1F5E），必须写 `0x8030`。向量文件名会进 Windows 路径，中文、空格、`*` 会触发 `OSError [Errno 22]`，临时文件统一用 ASCII 名。
- **证据**：实验5：首轮 8+2+16 行"失败"全是 `0xfffffff8` 对 `0xf8`；修正模型后全过

### K39 逐拍向量可以穿透多层子电路；复位/边沿映射要固定
- **坑/规则**：`ITAProbe.deepPropagate` 能处理 System→CU→IR 这类多层时序子电路：先标脏顶层再逐层递归，实测实验4 的 PC 在 T3 从 0→1、实验5 的 IR/RAM/Flag 按预期变化，不需要把系统展平。固定复位序列 `(0,1)→(1,1)→(0,1)→(0,0)`，之后 CLK 1/0 交替；边沿映射：`e%4==1` T1 取指、`2` T2、`3` T3 写回、`0` T0 空闲。Regs 不受 RST 清零（新仿真初值 0），RAM 初值 0 且不清零，PC/IR/Flag/CLK 计数器受 RST 清零。
- **证据**：实验4 系统 10 行、实验5 六个场景 600 行，均直接跑 系统连接，未展平

### K40 新增观测脚/叠放 ROM 后必须重跑"穿元件体"自检
- **坑/规则**：Regs 增加 Q0~Q3 后，子电路外观向下变高（System 里的体到 y=890），若沿用实验4 放在 y=900 的 RA4 分线器，其总线短桩（向上 20px）会穿进 Regs 体；实验5 直接把它下移到 y=940。4 片 ROM 叠在 x=800、y=120~420 时，CU 的 C 输入引线 140px 会横穿 ROM4 的体（660..800, 410..465），把引出距离改 80px。`board215.check()` 会把这两类报成"导线穿元件体"；不要忽略，移元件/缩短引线，不要改检查器。
- **证据**：实验5：第一次生成报 `rom@(800,420) (890,460)->(750,460)`；改 80px 并下移 RA4 分线器后六项自检 0 错误

### K41 2.7.1 素材的 source 头不能改成 2.15 头
- **坑/规则**：实验6 素材是 `<project source="2.7.1">`。把 source 改成 `2.15.0.2.exe`（其余 XML 不动）后，`16*16姓名显示` 的 17 行向量全挂——2.15 加载器对 2.7.1 子电路实例/引脚的兼容处理被跳过，子电路内部全 U。正确做法：保持 2.7.1 头，用 2.15.0.2 引擎 `ita_probe` 加载/验证；端口和元件几何本身是兼容的。
- **证据**：实验6：2.7.1 头 17/17 通过；改 2.15 头后 0/17，D1 单独求值却仍对（说明是子电路实例语义问题）

### K42 新造的 ROM 可能输出 U，直接复用素材 ROM 元素
- **坑/规则**：用 ElementTree 新建 `<comp lib="4" name="ROM">`（addrWidth=4、dataWidth=16、contents 文本）放进 2.7.1 素材电路时，地址/内容都正确但 Q 恒为 U；把同样内容写进**素材里已工作的 ROM 元素**（`copy.deepcopy` 后只改 `<a name="contents">`）就正常。新建元素的空白/序列化细节会影响 2.15 的 ROM 读取，别跟它较劲，直接借工作元素。
- **证据**：实验6：新建 ROM Q=U；deepcopy 32×32 示例 ROM 后 Q=0xB6AB

### K43 测试引脚不要在线段中段打 T
- **坑/规则**：为了读计数器 Q，在 `(100,210)->(130,210)` 的中间 `(115,210)` 引一条竖线，探针读到 U，ROM 也跟着 U；Logisim 的 T 接在 `CircuitState` 传播里并不总是可靠。测试引脚应从**元件端口**再引一条线（同一端口允许多条线），或用同名隧道接，不要在线段中段打 T。
- **证据**：实验6：中段 T 后 OCODE=U；改从 ROM Q 端口直接向上引线后 OCODE=0xB6AB

### K44 隧道不能放在已有导线上
- **坑/规则**：测试 `QW/WH` 时把隧道放在 `(300,100)/(300,120)`，正好压在 ROM→机内转区位码的 16 位竖线上，把 16 位网和 7 位网短接，整条显示链变 U。放隧道前先看该坐标有没有导线/端口；测试隧道放在空白区，靠同名标签连接。
- **证据**：实验6：QW 隧道压 x=300 竖线后 OCODE 都变 U；移到 `(250,100)/(250,120)` 后全恢复

### K45 子电路输出线必须从真实端口坐标起
- **坑/规则**：`例：机内转区位码` 实例在 `(380,50)`，输出端口是 `(380,50)`（区号）和 `(380,70)`（位号）。生成器把线画成 `(400,50)->(420,50)`，差 20px，转换输出悬空，后级字库全 U。接线前用 `ita_probe.ends` 核对子电路实例端口，不要凭外观矩形估算。
- **证据**：实验6：把起点从 400 改回 380 后，OQW=0x16、OWH=0x0B，显示链恢复

### K46 Counter 的 Q 与 carry 同边，竖线会短接
- **坑/规则**：2.15/2.7.1 Counter 的 Q 在 `(x,y)`、carry 在 `(x,y+10)`，都在右侧。从 Q 竖直向下引测试线会穿过 carry 端口，Q/carry 短接，计数器和后级都变 U。测试线应向右再拐，或从其他端口引。
- **证据**：实验6：Q 向下引线后 OCNT=U；改为从 ROM 侧读地址后恢复

### K47 D1 字扩展：低 12 位并联、高 2 位选片
- **坑/规则**：4 片 4K×32 组成 16K×32 时，14 位地址不能直接接 4K ROM 的 A（位宽不符）。用 14→2 Splitter：低 12 位接 4 片 A（并联），高 2 位接 32 位 4:1 MUX 的 sel；4 片 Q 进 MUX，输出接 D1。实验6 的 4 片 ROM A/Q 原本全悬空，这就是 D1=U 的根因。
- **证据**：实验6：9 个机内码 A14=(区-1)×94+(位-1)，D1 均等于选中的 Q

### K48 16×16 点阵的 D 是 32 位 = 两行
- **坑/规则**：16×16 字库的 D0~D7 每个 32 位，低 16 位是第 2i 行、高 16 位是第 2i+1 行；用 8 个 32→2 Splitter 拆成 16 路 16 位进 DotMatrix。分线器按 20px 间距排（与素材 16×16 字库内部一致），低 16 位先接上一行。
- **证据**：实验6：8 个分线器 + 16 行点阵，显示向量 17/17

### K49 bank3 不可达，但仍要接满 4 片
- **坑/规则**：GB2312 地址 `(区-1)×94+(位-1)` 最大约 8835（0x2283），高 2 位最多到 2，bank3 正常编码到不了。但题目要求 16K×32，仍要接 4 片（第 4 片 Q 输出 0 也没关系），不要因为“用不到”只接 3 片。
- **证据**：实验6：A14=0x2283 时 hi=2；bank3 输出 0，结构完整

### K50 2.7.1 ROM 的 cs 悬空可用
- **坑/规则**：素材 7 片 addr14 ROM 的 cs 都没接，仍能正常读出；4 片 addr12 的 cs 也悬空，接上地址和输出后同样工作。不要为了“保险”给 cs 加常量/门电路，反而可能引入新网络。
- **证据**：实验6：11 片 ROM cs 全悬空，D0~D7 与 D1 均正常

### K51 无头验证要把 Clock 换 Pin，交付保留 Clock
- **坑/规则**：`ita_probe` 不会自动驱动 Clock 组件；验证姓名显示时，在**临时副本**里把 Clock 换成输入 Pin，逐拍给 0/1；交付电路保留 Clock 供 GUI 模拟。不要为了验证把交付电路的 Clock 删掉。
- **证据**：实验6：临时副本 CLK Pin 跑 17 行；交付电路仍是 Clock

### K52 问答的地址位数别混
- **坑/规则**：页1 位数扩展图中地址端 8 位 → 256×16→256×32，地址 8 位、每单元 32 位；页2 1K×16→4K×32 是 10→12 位。两个例子的地址位数不同，写答案时不要统一写成 10/12。
- **证据**：实验6 问答电路：页1 写 8 位，页2 写 10→12 位

### K53 三极管是**单向开关**（in→out），下拉网络要把 GND 接在 in 侧
- **坑/规则**：2.15 的 `Transistor` 端口是 in=(x-40,y)、out=(x,y)、gate=(x-20,y-20)；数值只从 in 流到 out。CMOS 下拉网络若按"Q→晶体管→GND"接，Q 永远不会被拉到 0，表现为 Q 悬空（`U`/`E`）。正确接法是 **GND 接 in、Q 接 out**（上拉同理：VCC 接 in、Q 接 out）。
- **证据**：实验1 `2_晶体管门`：初版 A=B=1 时 Q=`U`；把串联/并联 n 管改成 GND→in 后，与非/或非真值表全对。

### K54 两个晶体管的输出侧别接在同一 x / 同一 y 上
- **坑/规则**：同一网里把 p 管输出与 n 管输出都接到同一竖线（同 x、上下相接）时，Logisim 把两段并成一整条，一个驱动源是 `Z`、另一个是有效值，结果整网变 `U`。每个驱动源要给**独立通道**（错开 10px 再拐到干线）。
- **证据**：实验1 NAND 的 p2 漏与 n2 漏同在 x=X+180，A=1,B=0 时输出 `U`；把 n 侧改到 x+220 拐上去后恢复 1。

### K55 8 位分线器的位口不是 `x+10-10i`
- **坑/规则**：2.15 实测——8 位分线器南向位口 `x+80-10i`、北向 `x-10-10i`（均 `y±20`）；≤4 位才是 `x+10-10i`。按 4 位公式接 8 位，后 4 位全部悬空（对应输出 `U`）。
- **证据**：实验1 `3_分离器`：初版 D3~D7 全 `U`；按实测公式后 D=0xA5 → 10100101，合并回 0xA5。

### K56 内建 Adder 的 `Cout` 是输入脚；Multiplier/Divider 的附加输入必须接 0
- **坑/规则**：2.15 的 Adder/Subtractor 端口是 A=(x-40,y-10)、B=(x-40,y+10)、S=(x,y)、Cin=(x-20,y-20)、**Cout=(x-20,y+20)（也是输入脚）**；求和正常，别指望进位输出。Multiplier/Divider 的 `(x-20,y-20)` 是 **width 位宽**的附加输入（C / Upper），悬空会让输出 `U`，要接 Constant 0；`(x-20,y+20)` 是附加输出。
- **证据**：实验1 `4_运算器`：Cin 接 0、Mul/Div 的 Upper 接 0 后，6±3 / 6×3 / 7÷2 全部正确。

### K57 Counter 设了 `max` 是向上计数
- **坑/规则**：K-notes 里"2 位默认向下计数"只适用于未设 max 的情形；`width=4, max=0x9` 实测是 **0→9→0 向上**，可直接当累加计数器用。
- **证据**：实验1 `6_计数器` + 早期探测：CLK 每来一拍 Q=0,1,2…，到 9 回 0。

### K58 向量文件里的中文引脚名会被截断
- **坑/规则**：`.vec` 是 UTF-8，但 Java 按平台字符集（GBK）读，中文引脚名会变成乱码且尾部字节被丢弃，报 `vector header pin not found in circuit: 1Y`。**引脚名用 ASCII**（A/B/SEL/Y、D0..D7），中文说明放到 Text 注释里。
- **证据**：实验1 初版 `1Y与门` 被解析成 `1Y`；改 ASCII 后一次通过。

### K59 自定义外观的锚点 = 6×6 框**左上角**，端口偏移要 +3
- **坑/规则**：`<circ-anchor x=ay>` 里存的是锚点框左上角，Logisim 以它的**中心**（x+3,y+3）为原点。所以实例端口 = `loc + (端口中心 − (anchor+3))`。按 `anchor` 直接算会整体差 3px，端口全部悬空：输入进不去、输出全 `x`，而 `ita_probe` 报端口坐标却是"对的"（它给的是外观几何）。
- **证据**：实验1 `5_运算器封装`：Y 全 `x`、封装左侧小方块与线头差 3px；把偏移从 (-87,-37) 改回 (-90,-40)（即减去 anchor+3）后 SEL=0..3 得 9/3/0x12/2。
- **附**：外观里的文字要写成 `<text font-family="SansSerif" font-size="11" text-anchor="middle" x=".." y="..">内容</text>`（内容在标签之间，不是 `text=` 属性）。

### K60 生成 .circ 时文本必须转义 `& < >`
- **坑/规则**：Text 组件里写 `Y = A || (B && C)` 会直接让 XML 解析失败（`元素类型 ... 必须由匹配的结束标记终止`，报的是所在行）。生成器里对 `text` 属性统一做 `&amp; &lt; &gt;` 替换。
- **证据**：实验1 `8a_A或B与C` 首次生成即报 `[Fatal Error] :1372:45`，转义后正常。

## L. Logisim-ITA 2.16.1.0（IO / 数码管 A~F，实验7）

L1~L13 全部是实验7 交付过程中实测的；几何数值取自 `SevenSegment.class` 反编译（2.16），
2.15 与 2.16 在这些点上行为一致。

### L1 `active="high"` 不是布尔值 → 数码管整块反相
- **坑/规则**：`Io.ATTR_ACTIVE` 由 `Attributes.forBoolean("active", ...)` 创建，XML 只认 `true` / `false`。写成 `high` 会被 `Boolean.valueOf` 解析成 `false`，表现为「该亮的段灭、该灭的段亮」；`ERRCOUNT` 仍为 0，`netcheck` / `circ271_check` 也查不出来，最容易被误判成「段位接错」。
- **证据**：实验7 `七段显示0~F`，D=1010 时只亮 d 段；把 7 处 `active="high"` 改成 `true` 后正常显示 A。
- **工具**：`sevenseg.py check` 会打印 `active` 取值并对非法值报警。

### L2 7-Segment Display 的 8 个输入脚（2.16 实测）
- **坑/规则**：a=(+20,0)、b=(+30,0)、c=(+20,+60)、d=(+10,+60)、e=(0,+60)、f=(+10,0)、g=(0,0)、dp=(+30,+60)，外框 `Bounds(-5,0,40,60)`；`SEGMENTS[]` 顺序 a,b,c,d,e,f,g（值 bit0~bit6，bit7=dp）。按直觉「北排 4 个 = a,b,c,d」接线会错掉 5 段。
- **证据**：早期版本把 c,d 接到北排、e,f,g 接南排，字模整体错位；按上表重接后 a→a…g→g。
- **工具**：`sevenseg.py check`（段位）/ `sevenseg.py table`（0~F 真值表）。

### L3 无 `<appear>` 的子电路：端口按 10px 打包，不能拿内部 Pin 坐标平移
- **坑/规则**：没有自定义外观时，Logisim 把输入排在左边、输出排在右边，间距固定 10px，顺序 = 内部 Pin 按 y 排序。内部 a 在 y=400、b 在 420（步长 20），实例上却是 `loc.y+0,10,20…`。照内部坐标接线会全部悬空。
- **证据**：`七段译码器0~F` 内部输出 y=400~520（步长 20），实例端口是 (500,300),(500,310)…(500,360)。
- **工具**：`ita_probe.py ends` 拿真实端口，别自己算。

### L4 Text 组件不支持 `&#10;` 换行
- **坑/规则**：一段 Text 里写 `&#10;` 不会换行，Logisim 把整段当一行画出来，还会向右压住别的元件。多行注释必须拆成多个 Text，逐行摆。
- **证据**：实验7 main 的思考题注释原本一整行压到「错误指示」LED 上；拆成 5 条单行 Text 后正常。

### L5 Pin / Text 的中文标签必须用带 CJK 字形的字体
- **坑/规则**：`Times New Roman bolditalic 18` 没有中文字形 → 引脚名显示成 □□□；改 `SansSerif bold 18` 正常。`Dialog plain 12` 也有 CJK，可放心用。
- **证据**：实验7 main 的 屏蔽字 / 传输数据 / 输出 / 正确 / 错误 曾全是方框。

### L6 子电路的 `clabel` 会画在外观块上
- **坑/规则**：子电路设了 `<a name="clabel" val="随机干扰"/>`，Logisim 就把这行字画在外观上；外观只有 60×40 时文字被挤压裁切，看着像「元件名称没正确显示」。要么把 clabel 留空（`val=""`）改在父电路用 Text 标注，要么把外观做大。
- **证据**：`9位随机干扰` 红块上出现被压扁的「随机干扰」。

### L7 共线重叠 = 短接；十字交叉 = 不连通
- **坑/规则**：同水平/垂直且区间**真重叠** → 短路；一条的端点落在另一条中段（T 接）→ 连通；双方都只是内点 → 不连通。不同区间并排（同 y 不重叠）是合法的，可放心当作并行通道。排线时给每路信号一个独立的水平层 + 独立竖直通道。
- **工具**：`netmap.py`（默认列端口级网表、`--overlap` 只查短接）。

### L8 端口级核对用 netmap，别只看「线画上去了」
- **坑/规则**：`netcheck.py` 只报位宽冲突，不报「接错位置」。数码管段位、分线器分支、子电路引脚这类必须按「端口 A 到底连到端口 B」核对；光看截图或数线根数都会漏。
- **证据**：一次误判把译码器输出的上下顺序看反，差点把本来正确的接法改坏；`netmap.py --comp` 一跑就露馅（a→a…g→g）。
- **工具**：`python netmap.py file.circ "电路名" --comp 七段译码器0~F`

### L9 GUI 自动化：按键会被别的窗口抢走
- **坑/规则**：本机 `GetForegroundWindow()` 返回 Logisim，但 `keybd_event` 与 `PostMessage(WM_CHAR)` 仍落进别的窗口（浏览器标签页），**点击是有效的**。所以「模拟打字」不可靠，中文字符更送不进去。需要改文字/改输入值时直接改文件，不要指望自动化键盘。
- **证据**：多次输入 "abc" 落到 Chrome 标签；同时 `SendMessageTimeout` 存活检查一直正常 —— 说明窗口没卡，只是键盘没进去。
- **工具**：`common/gui.py` 只用点击 / 滚轮 / 截图。

### L10 截图缩放：shift+滚轮两向可用，Ctrl 组合键不可靠
- **坑/规则**：`gui.wheel(h, n, shift=True, dy=+120)` 放大，`dy=-120` 缩小；`Ctrl+0` / `Ctrl+-` 在本机不生效。窗口宽约 1720px，电路宽 >1000 时先缩到 ~50% 再截；要看单个数码管就放大到 190% 左右。
- **证据**：全套电路 25% 一次入镜；放大到 190% 才看清 A 段的亮灭。

### L11 斜线 / 非 10 倍数的导线 → WireRepair 死循环，加载 OOM
- **坑/规则**：`WireRepair.doOverlaps` 用 `Wire.iterator()` 逐点建 HashMap；一旦出现斜线（dx、dy 同时非 0）或长度不是 10 的倍数，修复会反复拆分，表无限增长 → `java.lang.OutOfMemoryError: Java heap space`。GUI 里表现为「打开/保存时卡一下」，无头探针则直接 OOM 退出。
- **证据**：main 里出现 `(401,200)-(401,201)`（1px 短桩）+ `(401,201)-(440,200)`（斜线）后，`ita_probe` 加载直接 OOM；改回 `(401,200)-(440,200)` 立刻恢复，`main 不变式 20/20`。
- **工具**：`python netmap.py file.circ "电路名" --grid`（纯几何，不需要加载 Logisim）。
- **补充**：这类坏线常由「GUI 保存时 WireRepair 拆分」产生。批量生成后先跑 `--grid`，再用 GUI 打开；除非必要不要在 GUI 里保存交付文件。

### L12 想不起组件端口顺序/属性类型，直接拆 jar 看字节码
- **坑/规则**：`jar xf Logisim-ITA.jar com/cburch/logisim/std/io/SevenSegment.class` 再 `javap -p -c`，构造器里就是一串 `Port(20,0)`、`Port(30,0)…`，属性类型也能看到（`Attributes.forBoolean("active",...)`）。比翻文档快、比猜准。
- **证据**：L1、L2 的结论都是从 `SevenSegment.class` / `Io.class` 的字节码读出来的。

### L13 端口与导线差 1px → 改任意属性都卡死（WireRepair 死循环）
- **坑/规则**：在界面里改文字走的是 `TextTool → SetAttributeAction → CircuitTransaction → WireRepair.run → doOverlaps`；`doOverlaps` 按 `Wire.iterator()` 逐点建 HashMap。只要电路里有「端口和导线端点差 1px」「斜线」「长度非 10 倍数」的导线，修复就会反复拆出 1px 短桩/斜线段，点表无限膨胀 —— 现象是「改一个字立刻卡死」，进程吃到几个 GB；而无头加载往往正常，极易误判成中文输入法问题。
- **证据**：实验7 `main`：`奇校验编码` 输出口真实连接点 `(401,201)`（9 位端口的外观取整偏移），导线却画在 `(401,200)`。jstack 栈顶 `WireRepair.doOverlaps:176 → HashMap.put`，AWT-EventQueue 线程已占 2.4GB。把该子电路外观 `circ-port` 平移 (-1,-1)（端口变为 `(400,200)`）、导线改 400 后，`ATTR_OK 0ms`。
- **工具**：`python scripts/v271/attrprobe.py file.circ "电路名"`（8 秒超时判定，正常打印 `ATTR_OK`，卡死返回码 1）；几何自查 `netmap.py --grid`；查悬空端口用 `netmap.py --comp <元件>` 看该元件是否只出现一个网络。
- **补充**：多比特端口的外观取整会使端口落在 ±1 偏移上，且同一子电路的输入口与输出口偏移可能不同 —— **靠整体平移实例无法同时对齐两端**，改外观 `circ-port` 的 x/y（±1px，肉眼无感）是最省事的解法。

### L14 5.0 文件在 3.9 打开报「内置库不可用 / 找不到工具 [mapping] [toolbar]」
- **症状**：3.9 打开时连弹两个框——
  1. `2.11: 内置库"FPArithmetic"在此版本中不可用。`
  2. `在库中找不到工具 [mapping]` ×3、`[toolbar]` ×N（列表可滚动）
  电路本身没问题，Logisim 会"部分加载"，但用户会以为文件坏了。
- **根因**（三条互相独立，要一起清）：
  1. 5.0 写文件时会把**全部**库声明进去（`#FPArithmetic`/`#TCL`/`#Soc`…），
     哪怕一个元件都没用；3.9 没有这些库就直接报错；
  2. `<mappings>` 里的 `<tool map=... name=.../>` 在 5.0 不带 `lib=`，
     3.9 要求 `<tool lib="8" name="Poke Tool" map="Button2"/>`，缺 lib 会报找不到工具；
  3. `<toolbar>` 同理，条目必须带 `lib=`，否则每条都报错。
- **解决**（离线改写 XML，不动电路）：
  ```python
  used = set(re.findall(r'<comp lib="(\d+)"', src))
  # lib 只留用到的；带 <tool> 子块的压成自闭合 <lib desc=... name=.../>
  # <project source="5.0.0"> 改成 source="3.9.0"
  # <mappings>/<toolbar> 不要整段删，见下面的坑
  ```
  **lib 的 `name` 不要求连续**（3.9 接受 0/1/6），所以删库后不必重新编号，
  `<comp lib="6">` 原样保留即可。
- **⚠️ 别顺手把 `<mappings>` / `<toolbar>` 整段删掉**：
  删了虽然不报错，但 `2.11.circ` 打开后**项目工具条会变空**（只剩画布，没有手形/引脚/门），
  用户会以为"功能栏没了"。正确做法是**保留结构、给每条 `<tool>` 补 `lib="<库id>"`**：
  ```xml
  <mappings>
    <tool lib="8" name="Poke Tool" map="Button2"/>
    <tool lib="8" name="Menu Tool" map="Button3"/>
  </mappings>
  <toolbar>
    <tool lib="8" name="Poke Tool"/>
    <tool lib="8" name="Edit Tool"/>
    <tool lib="8" name="Wiring Tool"/>
    <tool lib="8" name="Text Tool"/>
    <sep/>
    <tool lib="0" name="Pin"><a name="facing" val="west"/></tool>
    <tool lib="0" name="Pin"><a name="facing" val="west"/><a name="type" val="output"/></tool>
    <sep/>
    <tool lib="1" name="AND Gate"/> … <sep/>
    <tool lib="5" name="D Flip-Flop"/><tool lib="5" name="Register"/>
  </toolbar>
  ```
  库 id 对照：`#Wiring`→0、`#Gates`→1、`#Memory`→5、`#I/O`→6、`#Base`→8
  （工具条里的 Poke/Edit/Wiring/Text 属 `#Base`，D-FF/Register 属 `#Memory`，
  用到的库即使没有元件引用也要**保留声明**，否则工具条那几条又会报"找不到工具"）。
  5.0 的 `Image` 工具 3.9 没有，去掉即可。
- **验证**：3.9 `-t stats` 无报错；同一电路的 `-t table --toplevel-circuit BCD`
  在 3.9 与 5.0 下 **512 行数据逐行相同**（表头写法不同：3.9 是 `a`，5.0 是 `a[4]`，
  比对时只比数据行）。
- **本例**：`测试/2.11.circ` 声明 13 个库只用到 3 个（Wiring/Gates/I-O），
  删到 3 个 + 去掉 mappings/toolbar 后 3.9 秒开、无任何弹窗。
